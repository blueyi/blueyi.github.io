## 1️⃣ AI 芯片

- 🔥 [Meta reuses old RAM in new servers with custom bridge chip](https://www.theregister.com/systems/2026/06/29/zuck-saves-meta-bucks-by-reusing-memory-from-old-servers-with-a-custom-cxl-asic/5263483)(HN 326):Meta 用一颗自研 CXL 桥接 ASIC 把老服务器上退役的 DDR4/DDR5 内存插回新服务器,通过 CXL.mem 语义暴露给新平台。在 HBM/DDR 供应吃紧、DRAM 现货价被 AI 拉爆的当口,这是超大规模厂商"资本支出摊薄"的教科书操作,也再度验证 CXL 内存池化正在从 PPT 走向机架级量产。
- [Apple Silicon Exec Explains Mac Mini AI Demand and On-Device Future](https://www.macrumors.com/2026/07/06/apple-silicon-exec-explains-mac-mini-ai-demand/)(HN 192):Apple Silicon 高管确认 Mac mini 出货被 AI 端侧推理需求推起来,统一内存架构成为核心卖点。同时释放"未来更多能力跑在设备上"的信号——对 8️⃣ 边缘端侧板块同样是重要背景。
- [Who Needs DRAM? We Have Fiber](https://arxiv.org/abs/2607.08407)(arXiv cs.AR):在 DRAM 合约价被生成式 AI 拉高的大背景下,提出 **Fiber Memory** 架构,重新审视光纤在超大规模数据中心的角色——将部分远端内存访问下沉到光互连而非扩 DRAM,是一条极其激进但方向正确的路线。
- [SPEC CPU2026: Characterization, Representativeness, and Cross-Suite Comparison](https://arxiv.org/abs/2605.03713)(arXiv cs.AR):专用加速器主导 AI 负载,但 CPU 仍是调度加速器和跑日常服务的关键。文章系统评估 SPEC CPU2026 的代表性,给通用 CPU 微架构与基准选型提供新参考。

## 2️⃣ AI 编译器与框架

- [SPL: Orchestrating Workflows with Declarative Deterministic-Probabilistic Composition](https://arxiv.org/abs/2607.07727)(arXiv cs.PL):**结构化提示语言 SPL**,把 AutoGen/LangGraph 那套 LLM 编排与 SymPy/Lean 那套符号计算统一到一个声明式语言里,提供 GENERATE / EVALUATE 两个原语——概率计算和确定性计算在同一份规范里协同,可以看作面向 Agent 时代的"编译器 IR"。
- [Environment-Sensitive Lexicographic Disambiguation for Contextual Parsing](https://arxiv.org/abs/2607.07728)(arXiv cs.PL):基于全局可变上下文做解析树消歧的确定性算法,锦标赛式淘汰竞争推导——对 DSL / 编译器前端在处理歧义语法时有直接工程价值。
- [A Top-Down Deriving Mechanism in Haskell](https://arxiv.org/abs/2607.07732)(arXiv cs.PL):对 Haskell `deriving` 机制的扩展,支持组合数据类型和多参数场景;由此外溢到 Rust trait / Java Lombok 等以派生生成样板代码的生态。
- [Potential Functions as Types](https://arxiv.org/abs/2607.08547)(arXiv cs.PL):在依赖类型代价验证系统 Calf 中,把物理学派(potential function)和银行家派(type-level credit)两种摊销分析视角统一起来,面向可证明的性能上界。

## 3️⃣ AI 推理优化(数据中心)

- [CTA-Pipelining: A Latency-Oriented Spatial Scaling Method for Multi-GPU Systems](https://arxiv.org/abs/2607.07862)(arXiv cs.DC):多 GPU 系统正从"高速网络互连"演进到"紧耦合共享内存",而现有软件栈仍把 NVLink/NVSwitch 当成快网卡。作者提出以 CTA(线程块)为粒度的空间流水线,针对 LLM 服务从吞吐导向切换到延迟导向的新范式——直接对应 B200 / GB200 集群上的低延迟 serving 场景。
- [Toward a Unified GPU-Aware OpenSHMEM Specification](https://arxiv.org/abs/2607.08006)(arXiv cs.DC):随下一代 HPC/AI 系统通过高速内存 fabric 把更大设备域紧耦合起来,PGAS 模型天然适合表达细粒度远端访问,文章推动 GPU-aware OpenSHMEM 规范统一化,与 NCCL/NVSHMEM 生态形成呼应。
- [On the Limitations of Non-GPU AI Accelerators for Large-Model Inference: A Field Study of MoE and Multimodal Serving on Huawei Ascend](https://arxiv.org/abs/2607.08215)(arXiv cs.DC):**16 卡 Ascend 910 + CANN + vLLM-Ascend** 部署 LLM-as-a-judge 与多模态服务的实测报告,系统记录"离开 CUDA"的真实工程代价。国产替代路径上一份难得的第一手数据。
- [Jet-Long: Efficient Long-Context Extension with Dynamic Bifocal RoPE](https://arxiv.org/abs/2607.07740)(arXiv cs.LG):面向 RAG / Repo-level Coding / Agent 长上下文场景的零样本扩窗方法,动态双焦 RoPE 在超预训练窗口一个量级的输入上仍能工作——对开源权重的生产化部署非常实用。
- [Uncertainty-gated selection for block-sparse attention](https://arxiv.org/abs/2607.07724)(arXiv cs.LG):Block-sparse attention 的 top-k 选择过于短视,作者提出信息价值路由器,当第 k 与第 k+1 块得分接近时动态追加预算——直击长上下文稀疏注意力"证据丢块"的老毛病。

## 4️⃣ 数据中心与基础设施

- 🔥 [Meta reuses old RAM in new servers with custom bridge chip](https://www.theregister.com/systems/2026/06/29/zuck-saves-meta-bucks-by-reusing-memory-from-old-servers-with-a-custom-cxl-asic/5263483)(HN 326):**超大规模 capex 优化的标志性事件**——自研 CXL ASIC 把旧内存翻新入池,直接压低单位 token 的资本折旧。已在 1️⃣ 详述,此处点名。
- [Who Needs DRAM? We Have Fiber](https://arxiv.org/abs/2607.08407)(arXiv cs.AR):把光纤定位为"远端内存介质"的机架级/园区级架构提案,若成立将重塑数据中心 memory tier 与光互连 roadmap。
- [Adaptive Row Selection Meets Asynchrony in Randomized Kaczmarz](https://arxiv.org/abs/2607.08313)(arXiv cs.DC):共享内存机器上无锁并发 Kaczmarz 求解器的首个系统研究,面向大规模稀疏最小二乘/层析重建——HPC + AI 混合负载相关基础工作。
- [Empirical Analysis of GPU Frequency Behavior Under ML Workloads](https://arxiv.org/abs/2607.08307)(arXiv cs.DC):实测 NVIDIA GPU 在 ML 负载下的频率行为,低端 GPU 的频率受最近约 80ms 历史强烈影响——直接挑战了很多 SOTA 延迟预测模型的隐含假设,数据中心调度和 SLO 建模都要重看。
- [Coded Task Offloading for Fluid Computing: A Privacy-Aware Approach under D2D Networks](https://arxiv.org/abs/2607.08440)(arXiv cs.DC):面向 Fluid Computing 的编码卸载方案,在 D2D 场景兼顾隐私与对抗性执行——把"云-边-端"资源作为流体统一编排的实践参考。

- [SASGeo: Stability-Aware Semantic Map Localization for GNSS-Denied UAVs](https://arxiv.org/abs/2607.07737)(arXiv cs.RO):无 GNSS 环境下 UAV 的语义地图定位框架,通过稳定持久结构对抗季节/光照/视角/传感器差异——具身智能里"世界模型的定位锚点"这条线。
- [Time-to-Collision Based Dynamic Obstacle Avoidance Using Pretrained Vision Models](https://arxiv.org/abs/2607.07885)(arXiv cs.RO):完全走真实数据、不依赖仿真到现实迁移的动态避障方案,数据效率与可解释性并重——对小团队真机部署极友好。

## 7️⃣ AI 自动算子与代码生成优化

- [A Theoretical Framework for Stochastic Activity Prediction in Tensor Accelerator Wallace-Tree Multipliers](https://arxiv.org/abs/2607.08002)(arXiv cs.AR):在张量加速器的 Wallace-Tree 乘法器上引入**随机活动预测 SAP**,对稀疏操作数下的动态功耗做在线自适应门控,填补了零检测和结构性功耗门控之外的一片空白——本质是"用小模型替编译器/RTL 做微观自动调优"。
- [FPGN: Redefining Ultra-Fast Programmable Gate-based Neural Acceleration with Differentiable LUTs](https://arxiv.org/abs/2607.08427)(arXiv cs.AR):把 FPGA 的 LUT 本身当作**可微分神经算子**训练,而不是继续把 LUT 当算术运算的乐高——纳秒级推理场景下,是 AI 与硬件联合设计的又一次前沿尝试,与 AlphaEvolve/FunSearch 精神相通。
- [REFORGE: A Method for Benchmarking LLMs' Reverse Engineering Capabilities in Decompiled Binary Function Naming](https://arxiv.org/abs/2607.07738)(arXiv cs.PL):严肃对待 LLM 在反编译函数命名这类任务里的能力评测——把"函数级 ground truth 构造"本身作为核心问题重做,给 AI 参与逆向/安全工作流提供扎实的量化基准。
- [CRIMP: Compact & Reliable DNN Inference on In-Memory Processing via Crossbar-Aligned Compression](https://arxiv.org/abs/2607.08015)(arXiv cs.AR):存内计算 crossbar 上的量化与非理想性自适应压缩,消灭浮点尺度因子对 FP 处理器的依赖——把算法-架构协同压缩推进一大步。
