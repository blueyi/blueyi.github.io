## 2️⃣ AI 编译器与框架

- **LLVM 翻译验证正式引入大模型 + Lean**:论文把 LLM 用于生成/补全 Lean 证明,缓解 Alive2 这类 SMT 方法在规模上的可扩展性瓶颈。这是"形式化验证 + LLM"在编译器基础设施里最扎实的一次落地尝试,比单纯"LLM 写代码"更接近可交付。[arXiv 2609.19583](https://arxiv.org/abs/2609.19583)
- **Splyce:在 MLIR 中把稀疏-稀疏 coiteration 循环自动向量化**。做法是双路径执行模型 —— 用选择性谓词化把"坐标求交"和"指针管理"解耦,顺带把数据相关分支整体消除。稀疏张量收缩长期是 loop vectorization 的死角,这条直击 MLIR 生态的痛点。[arXiv 2609.19410](https://arxiv.org/abs/2609.19410)
- **The Output-Space Hypothesis:张量程序的枚举式等价性检查**。传统做法是在随机输入上做 differential testing,但深度学习的张量程序错误往往落在特定输入区间,该工作转向输出空间做枚举验证,对 torch.compile / XLA 这类图编译器的正确性回归测试有直接借鉴价值。[arXiv 2609.19611](https://arxiv.org/abs/2609.19611)
- **FloatLib:Lean 4 中经过机器验证的任意精度浮点算术库**,首次在 Lean 里统一 IEEE 二进制/十进制、任意位宽 posit、P3109 与用户自定义格式及舍入规则,并支持高效认证执行。对浮点语义敏感的编译器验证(常量折叠、快速数学优化)是基础件。[arXiv 2609.19352](https://arxiv.org/abs/2609.19352)
- 另外两篇面向编译期与求解器性能的短文也值得一提:**用语义保持的重写规则对 SMT 求解器的浮点理论做蜕变测试**(性能而非正确性视角),[arXiv 2609.19735](https://arxiv.org/abs/2609.19735);以及 **J 语言中 NumPy 广播的 verb rank 表达**,为数组语言的形状语义提供另一种形式化路径。[arXiv 2609.16064](https://arxiv.org/abs/2609.16064)

## 3️⃣ AI 推理优化(数据中心)

- 🔥 **NVIDIA Vera Rubin NVL72 在 MLPerf Inference v6.1 首次亮相即拿下领先性能**。官方叙述的三大杠杆是:单系统性能、基础设施扩展效率、持续软件优化 —— 核心叙事仍是 "tokens per watt" 决定推理经济性。这是 Rubin 代际推理能力的首个公开可复现基线,后续 SGLang / TensorRT-LLM 的优化空间以此为准绳。[NVIDIA Blog](https://blogs.nvidia.com/blog/vera-rubin-nvl72-mlperf-inference/)
- **"静默数据损坏(SDC)"成为 arXiv 今日最集中主题,三篇连发**:①针对量化整数 GPU 算术 —— INT32 累加器既无奇偶校验也无 ECC,瞬时故障会返回合法但错误的整数且不触发中断,该工作把校验和式 ABFT 从"二值判定"推进到可定位;[arXiv 2609.19743](https://arxiv.org/abs/2609.19743) ②FP-Sketch 提出张量核 GEMM 之后的**事后验证器**,无需把 ABFT 融进 kernel 或编码操作数;[arXiv 2609.19758](https://arxiv.org/abs/2609.19758) ③PaRID 用 LLM 调优的指令复制做并行软件软错误检测,只付编译期成本、无需动态 profiling。[arXiv 2609.19531](https://arxiv.org/abs/2609.19531) 大集群训练中断的现实是"以整节点为单位处置",这类细粒度定位是该问题的关键一步。
- **MeshKV:面向 Transformer 解码加速器的 NoC KV Cache fabric**。把 KV block 以 packetized flow 在轻量片上网络里搬,并用 TaKV affine striping 打散集中式内存路径的流量,直接针对长上下文服务的带宽瓶颈。[arXiv 2609.19207](https://arxiv.org/abs/2609.19207)
- **华为 OceanStor KV cache 存储方案**,面向超大规模 AI 数据中心,走的是"KV 缓存外置到存储层"的路线,与 GPU 侧显存分层管理形成对照。[Blocks & Files](https://www.blocksandfiles.com/flash/2026/09/18/huaweis-oceanstor-kv-cache-storage-for-hyper-scale-ai-data-centers/5297405)
- **Kubernetes 原生质量感知路由(ASRB)**:把基础设施指标、响应时延与应用级质量信号联合打分,面向计算连续体上的 ML 推理服务做动态路由。[arXiv 2609.20497](https://arxiv.org/abs/2609.20497)
- 训练/压缩侧两条:**分块并行(Block Parallelism)优化长上下文扩散语言模型训练**,针对 block diffusion 里"块间自回归 + 块内并行去噪"的注意力通信与激活内存双重约束;[arXiv 2609.19242](https://arxiv.org/abs/2609.19242) 以及**层课程学习驱动的 LLM 压缩**,由易到难逐层做教师-学生知识迁移。[arXiv 2609.19213](https://arxiv.org/abs/2609.19213)
- HuggingFace 放出**用 100 步 GRPO 把 350M 小模型的结构化输出能力训好**的实操博文,以及 **HF Jobs 上跨桶 + proxy、无需 NCCL 的异步 GRPO LoRA** 方案 —— 强化学习后训练的门槛正在被工程化压低。[HF Blog](https://huggingface.co/blog/grpo-with-trl-ifstruct) / [HF Blog](https://huggingface.co/blog/asyncgrpo-lora-hfjobs)

## 7️⃣ AI 自动算子与代码生成优化

- **Rosetta:用多智能体 LLM 流水线自动生成"第一性原理"性能模型**。分析型性能模型(从硬件参数推导吞吐/加速比)的可验证性远高于实测曲线,但因为要专家手工花数周,极少随架构论文发表 —— Rosetta 想把这个环节自动化,对算子/架构性能分析的可复现性是实质推进。[arXiv 2609.19376](https://arxiv.org/abs/2609.19376)
- **《Do AI Agents Understand Computer Architecture?》** 提出一个尖锐的方法论问题:现有评测只能说明"某个设计变好了",无法说明"Agent 是在理解机器,还是在它所不理解含义的旋钮上做熟练搜索"。只有前者才可迁移到下一个架构。这是自动化硬件/算子优化领域最需要的一类评测反思。[arXiv 2609.19387](https://arxiv.org/abs/2609.19387)
- **CovR:以推理引导的强化学习做覆盖率感知的硬件验证**。设计验证占硬件开发总投入可达 70%,而现有 LLM 生成 testbench 的工作多只看功能正确性、忽略覆盖率质量 —— CovR 正是补这个缺口。[arXiv 2609.19189](https://arxiv.org/abs/2609.19189)
- **"LLM 在哪里结束、可靠决策从哪里开始"——ANVIL 编译器架构**:自然语言优化问题转求解器代码的流程中,只在一次调用里使用语言模型(配合基于约束的引导),把数学建模与可执行代码生成彻底分离。这类"收缩 LLM 作用域"的设计取向,比全链路 LLM 更接近可交付。[arXiv 2609.19545](https://arxiv.org/abs/2609.19545)
- **工程界的两个直接案例**:微软**用 agentic 方式把 Copilot runtime 移植到 Rust,花费 12 万美元**,编译器本身"对 LLM 的胡闹毫无波澜";[The Register](https://www.theregister.com/devops/2026/09/18/microsoft-agentically-ports-copilot-runtime-to-rust-for-120k/5297549) 千问办公协助国家天文台科研团队 **3 天、不到千元**搭出科研级望远镜数字化仿真系统,其产出数据后续将用于训练望远镜控制模型(VLA)。[雷锋网](https://www.leiphone.com/category/industrynews/HlXq3tJy48q1NubA.html)

## 8️⃣ 边缘与端侧推理

- **SiliconBench:统一内存桌面上的 LLM 服务评测**。用速度、内存、保真度三个维度评估九款 Apple Silicon 推理引擎,覆盖 Qwen3 / Qwen3.5 / Gemma 4 的对话与 agent 场景,并用分类任务检查质量回退 —— 直指"只看 tok/s 排名会忽略内存余量与输出保真度"的现实问题。[arXiv 2609.19169](https://arxiv.org/abs/2609.19169)
- **MiX:微反缩放(micro-inverted-scaling)实现端到端低比特 VLM 加速**。多模态 token 之间极大的动态范围差会让标准块格式出现"microscaling collapse",而边缘加速器受面积与功耗约束必须端到端量化,该工作正面解这个矛盾。[arXiv 2609.19683](https://arxiv.org/abs/2609.19683)
- **Xronos:面向边缘 CPU 协同 LLM 微调的异构感知张量并行**。现有协同微调(几乎全为 GPU 边缘设备设计)依赖流水线并行,但 IoT 网关、智能家居中枢、车载计算机的主流是 CPU —— 这条把张量并行搬到了 CPU 异构场景。[arXiv 2609.19909](https://arxiv.org/abs/2609.19909)
- **REACT:全脉冲状态空间模型做实时事件驱动感知**。事件相机有微秒级时间分辨率,但多数学习方法把事件累积成帧或时间桶,引入积分延迟 —— REACT 全程脉冲化以消除这个延迟,对高速机器人反应是结构性改进。[arXiv 2609.19204](https://arxiv.org/abs/2609.19204)
- **端侧硬件与 OS 侧动态**:OPPO 随 ColorOS 17 把手机 OS 推向 **AgentOS** 形态;[InfoQ](https://www.infoq.cn/article/gDSf7xBmd08H0eB0GG11) 搭载豆包手机助手的**努比亚 NaviX Ultra 5499 元起售**,被定位为"AI 智能体手机从工程样机迈入规模化量产商用"的标志。[新智元](https://aiera.com.cn/2026/09/18/other/admin/114312/) 另有分布式边缘推理在多视角检测上的实验研究。[arXiv 2609.20009](https://arxiv.org/abs/2609.20009)
