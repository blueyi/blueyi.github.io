# 📡 AI Infra 日报 · 2026-07-03(周五)

> 覆盖窗口:2026-07-01 ~ 2026-07-03 · 信息源:Hacker News / arXiv

## 1️⃣ AI 芯片
- **PQC 专用 NTT 加速器新微架构** — [High-Performance NTT Accelerators for PQC](https://arxiv.org/abs/2607.00621) 面向后量子密码(ML-KEM/Kyber、ML-DSA/Dilithium)的大次多项式运算,提出统一冗余算术 + 精调微架构来加速 NTT 这一核心原语。虽属密码硬件,但对未来数据中心安全协处理器的裸片设计有参考价值。
- **GPU 能效"甜点区"建模** — [Modeling and Chasing the Energy-Efficiency Sweet Spots in Modern GPUs](https://arxiv.org/abs/2607.00819) 在 A40 / A100 / H100 / H200 四代卡上,用 GROMACS、AMBER 分子动力学与 FIRESTARTER 压力测试刻画硬件配置对"每解能耗"的影响,给出锁频/功耗墙下的能效最优区间——对超算与训练集群的功耗预算调优直接有用。
- 背景:本窗口 Nvidia/AMD/Intel/TSMC/HBM 无独立重大发布。

## 2️⃣ AI 编译器与框架
- **块程序的可证明变换** — [Certificate-Carrying Transformation of Event-Driven Block Programs](https://arxiv.org/abs/2607.00563) 把 Scratch 等块状语言的优化改写成"携带证书"的源到源重写:不可信优化器提出改写,可信 fail-closed 检查器重算每个副条件后才接受。为编译器优化的可信化提供了轻量范式。
- **实用化区间精化类型** — [Practical Range Refinement Types with Inference](https://arxiv.org/abs/2607.00824) 针对精化类型标注负担过重的痛点,提出带推断的区间精化类型,降低主流语言接入静态验证的门槛。
- 背景:tinygrad / MLIR / TVM / XLA / Triton / Mojo 本窗口无独立重大更新。

## 3️⃣ AI 推理优化(数据中心)
- **长时程 Agent 服务的上下文工程** 🔥 — [SmoothAgent](https://arxiv.org/abs/2607.00151) 直击多轮 Agent 上下文持续膨胀、offloading/reduction/isolation 引入巨大上下文变换开销的问题,提出"前瞻式上下文工程"(Lookahead Context Engineering)来高效服务长时程 LLM Agent。是当下 Agent 基础设施最贴地的一篇。
- **MoE 解码路由感知专家局部性** — [ELDR: Expert-Locality-Aware Decode Routing for PD-Disaggregated MoE Serving](https://arxiv.org/abs/2607.00466) 指出 PD 分离服务中,现有解码路由只均衡负载并不够:MoE 下等负载 worker 因每步需加载 batch 激活的全部专家权重而延迟迥异,遂提出感知专家局部性的解码路由。对 vLLM/SGLang 类 MoE 服务栈有直接工程意义。
- **稀疏检索存储压缩 97%** — [Asymmetric Quantization: Near-Lossless Retrieval with 97% Storage Reduction](https://www.mixedbread.com/blog/asymmetric-quant)([HN 101 分](https://news.ycombinator.com/item?id=48724127))非对称量化实现近无损向量检索、存储降 97%,对大规模 RAG/向量库的成本结构影响显著。

## 4️⃣ 数据中心与基础设施
- **Promise-Future 集群异步同步** — [Promise-Future Synchronization for Cluster AMT Runtimes via MPI One-Sided Communication](https://arxiv.org/abs/2607.00303) 扩展 Itoyori AMT 运行时,突破"future 创建即绑定生产者、读者数编译期固定"的限制,支持动态依赖表达——对超算级异步多任务调度是底层改进。
- **微服务可用性运行时模型** — [Stochastic Connectivity as the Foundation of a Runtime Model for Microservice Availability Analysis](https://arxiv.org/abs/2607.00740) 用分布式追踪 + 部署元数据推导端点级可用性,替代昂贵高风险的混沌工程,给大规模服务集群提供更廉价的可用性证据。
- **自动扩缩容仿真框架** — [CloudyGUI](https://arxiv.org/abs/2607.00455) 提供带 GUI 的 Python 云工作负载仿真与预测框架,便于研究者验证资源管理与 auto-scaling 策略。

- **可解释性可复用性协议** — [Representation as a Bottleneck for Mechanistic Interpretability: The Manifestation Unit Protocol](https://arxiv.org/abs/2607.00089) 针对机制可解释性成果(选择性表、电路图、特征列表)锁在各自 notebook 里、不可组合/不可查询的问题,提出统一的"表现单元"协议使结果可复用可行动。

## 6️⃣ 具身智能
- **空间场景图 VLA 基准** — [EmbodimentSemantic](https://arxiv.org/abs/2607.00020) 面向 VLA 机器人操作缺乏显式空间表征(支撑、包含、遮挡、深度关系)的痛点,推出空间场景图数据集与基准。
- **何时该个性化家庭物品搜索** — [When to Personalize Household Object Search](https://arxiv.org/abs/2607.00022) 提出 PerSim 刚性门控混合策略,权衡"住户特质先验"与"群体频率基线"。
- **缆索悬挂载荷协同运输** — [Decentralized Geometric Control for Cable-Suspended Payload Transport](https://arxiv.org/abs/2607.00024) N 架四旋翼无中心协调、带自适应质量估计的四层分层控制。
- **仿蝇脑拓扑的鲁棒导航网络** — [FLYNN](https://arxiv.org/abs/2607.00025) 直接由果蝇突触级连接组导出 RNN 架构,提升新环境/感知缺失下的鲁棒性;另有 [SE(3) 不变卡尔曼滤波机械臂状态估计](https://arxiv.org/abs/2607.00026)、[Argoverse 2 城市减速行为分类器](https://arxiv.org/abs/2607.00027)、[社交机器人导航的图轨迹学习](https://arxiv.org/abs/2607.00028)、[面向具身智能的记忆原生非地面网络](https://arxiv.org/abs/2607.00029) 等一批 cs.RO 新作,覆盖状态估计、驾驶行为、社交导航与天地一体连接。
- **DIY 开源扫地机器人** — [Oomwoo](https://makerspet.com/blog/building-an-open-source-robot-vacuum-meet-oomwoo/)([HN 453 分](https://news.ycombinator.com/item?id=48755005))开源可自制扫地机器人,消费级具身硬件民主化的有趣样本。

## 7️⃣ AI 自动算子与代码生成优化
- **自进化 Agent 的强化学习系统** — [Next-Generation Agentic Reinforcement Learning Systems Enable Self-Evolving Agents](https://arxiv.org/abs/2607.01120) 指出生产环境中 LLM Agent 的权重、系统提示、工具库、上下文 harness 在部署时全部冻结,改进需人工离线循环;提出下一代 agentic RL 系统支撑自进化,是"AI 自动改进 AI"方向的系统级探索。
- **LLVM 编译器 issue 求解基准** — [LLVM-Bench](https://arxiv.org/abs/2607.00700) 首个大规模 LLVM 编译器 issue 解决基准,填补 LLM 在系统级编译器(而非算法题)上求解能力评测的空白——对"LLM 驱动编译器"落地评估很关键。
- **算法适应性代码生成基准** — [AlgoBench](https://arxiv.org/abs/2607.00062) 质疑 HumanEval/LiveCodeBench 高通过率不等于真会算法推理(题面/题解泄漏进训练),构造衡量算法适应能力的新基准。
- **CursorBench 3.1** — [Cursor 评测集更新](https://cursor.com/evals)([HN 157 分](https://news.ycombinator.com/item?id=48756840))代码 Agent 评测持续演进,是衡量 LLM 编码/代码生成能力的行业风向标。

## 8️⃣ 边缘与端侧推理
- **PQC 端侧 NTT 加速微架构** — [High-Performance NTT Accelerators for PQC](https://arxiv.org/abs/2607.00621)(见第 1 类)以统一冗余算术做定制硬件,对功耗/面积受限的端侧安全芯片(NPU 旁的密码协处理器)同样适用,可为端侧后量子加密提速。
- 背景:本窗口 llama.cpp / MLC-LLM / ExecuTorch / MLX / Core ML / NPU(Hexagon/ANE/Jetson)/ 小模型 / 极低比特量化(BitNet/INT4)无独立重大动态。
