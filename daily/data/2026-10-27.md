## 1️⃣ AI 芯片

- 🔥 **[台积电 A14 节点终结 SRAM 微缩八年停滞,存储单元面积首降 19%](https://www.cnbeta.com.tw/articles/tech/1583950.htm)** — 自 N5 量产以来 6T SRAM 单元面积一直卡在约 0.021 平方微米,逻辑密度年年涨、存储单元却原地踏步。A14(计划 2028 投产)首次把存储单元面积压下来 19%,这对大模型权重常驻、片上 SRAM 做 KV/激活缓冲的设计意义重大:过去几年"算力靠堆、片上缓存不涨"的结构性失衡开始松动。
- 🔥 **[Micron 计划用晶圆键合 + High-NA EUV 做下一代 DRAM,同时开发垂直 HBM 与垂直边缘推理内存](https://www.tomshardware.com/pc-components/dram/micron-plans-to-use-wafer-bonding-and-high-na-euv-for-next-gen-dram-company-also-developing-vertical-high-bandwidth-memory-and-vertical-edge-inference-memory-integrated-directly-on-top-of-processors)** — Micron 明确拒绝 4F2 路线,改走晶圆键合叠加 High-NA EUV;更值得关注的是"Vertical Edge Inference Memory"——把推理内存直接堆到处理器上方。存储厂开始越过 JEDEC 的标准件角色,直接参与算力封装定义。
- **[Nvidia 绕过 JEDEC HBM 标准](https://www.blocksandfiles.com/ai-ml/2026/10/26/nvidia-sidesteps-jedec-hbm-standard/5305323)** — 报道称 Nvidia 未走 JEDEC 的 HBM 标准化路径推进自有方案。若成惯例,HBM 从"通用标准件"退化为"绑定特定加速器的定制件",供应链议价、二手复用与多 vendor 兼容性都会变差,长期看是生态碎片化风险。
- **[垂直 DRAM 堆叠把散热设计空间推到 HBM-on-GPU 之外(imec)](https://semiengineering.com/vertical-dram-stacking-expands-thermal-design-space-beyond-hbm-imec/)** — imec 评估把 DRAM die 垂直旋转堆在 GPU 上方、并在层间留冷却腔,作为 2.5D 之外的替代路线。与上一条合看:2027 之后的内存竞争不只是带宽,而是"带宽 + 可散热性"的联合约束。
- **[RISC-V、Arm、x86 在 HPC 负载上的同条件对比(arXiv 2610.32632)](https://arxiv.org/abs/2610.32632)** — 用统一软件栈与负载重做了三种 ISA 的评测,并把能效纳入比较。此前结论互相矛盾主要源于平台/方法论不一致;这类"同条件基线"是 RISC-V 进入超算采购清单前必须补齐的证据。

## 2️⃣ AI 编译器与框架

- 🔥 **[AI 教科书全错:底层公式 Bug 曝光,PyTorch/JAX 均受影响,Gemini 率先自我修复](https://aiera.com.cn/2026/10/27/other/admin/120748/ai%e6%95%99%e7%a7%91%e4%b9%a6%e5%85%a8%e9%94%99%ef%bc%81%e5%ba%95%e5%b1%82%e5%85%ac%e5%bc%8f%e6%83%8a%e5%a4%a9bug%e6%9b%9d%e5%85%89%ef%bc%8cgemini%e7%8e%87%e5%85%88%e8%87%aa%e6%88%91%e4%bf%ae%e5%a4%8d/)** — Google DeepMind 研究科学家 Jon Barron 披露:某个被教科书与主流框架共同沿用的公式本身有误,PyTorch、JAX 的实现都照抄了这个错误。这类"误差随规模放大但不报错"的 bug 是最难定位的一类,也说明框架级数值正确性验证(而非仅算子单测)应成为发布门禁的一部分。
- **[MERA:面向量子电路的中间测量误差感知编译框架(arXiv 2511.10921)](https://arxiv.org/abs/2511.10921)** — 中间测量(MCM)支撑量子比特复用与动态控制,但会引入测量串扰、闲置退相干、reset 不保真等误差,且误差率逐比特不同。MERA 把误差画像喂进编译决策——这与经典编译器用 profile 指导调度是同构思路,编译器的"硬件感知"边界正在从延迟/带宽扩展到噪声分布。

## 3️⃣ AI 推理优化(数据中心)

- 🔥 **[OpenAI 与 Anthropic 数月内把 LLM 价格砍了最多 80%,为什么?](https://minimaxir.com/2026/10/cheap-llms/)** — 413 分的讨论文,把降价拆成三重驱动:单位推理效率提升、更小的可替代模型(蒸馏/路由)、以及竞争性定价。价格战的真实含义是"每 token 的有效算力成本"成为比模型榜单更硬的竞争指标,推理栈优化直接换算成毛利。
- 🔥 **[OpenAI 低成本新模型 GPT-6.1 Terra:每项任务成本仅 Claude Opus 5.5 的九分之一](https://www.ithome.com/1/018/200.htm)** — 定位复杂电脑操作任务,主打视觉推理与桌面软件操作,同时提升事实准确性与编程能力,面向发票处理、技术图纸解读等企业自动化。这是"模型能力分层 + 任务级成本"取代"单一旗舰定价"的明确信号。
- **[修复 vLLM 中的工具调用准确率问题](https://www.ubicloud.com/blog/fixing-tool-call-accuracy-in-vllm)** — 144 分。Agent 场景里 tool-call 的解析/约束解码一旦偏差,错误会静默传导成错误动作而非错误文本;这类问题落在推理框架的语法约束与采样层,而不是模型权重上。
- **[KVStream:面向大规模 LLM 服务 KV 缓存的自适应并行存储管理(arXiv 2610.31827)](https://arxiv.org/abs/2610.31827)** — 长上下文 agent/编码/文档负载复用前缀,KV 已超出 GPU 与主机内存。现状是单节点 NVMe 承担全部检索,而节点已挂载的并行文件系统几乎不承载推理流量;KVStream 把检索摊到并行存储层,让存储 I/O 不再卡在推理步的关键路径上。
- **[HAWK:GPU-NPU 相位分离推理的异构感知 KV 缓存传输(arXiv 2610.29873)](https://arxiv.org/abs/2610.29873)** — prefill 吃算力、decode 吃带宽,GPU 擅长前者、NPU 在后者更划算。HAWK 解决的是 P/D 分离后 KV 跨异构加速器搬运的效率问题——异构 P/D 能否落地,瓶颈从来不在算力而在搬运。
- **[用 Dynamo + Liqid CXL 共享内存击穿 KV cache 内存墙](https://www.blocksandfiles.com/architecture/2026/10/26/breaking-the-kv-cache-memory-wall-using-dynamo-and-liqid-cxl-shared-memory/5305130)** — 与 DapuStor 的 KV cache NVMe SSD offload 方案([同源报道](https://www.blocksandfiles.com/flash/2026/10/26/dapustors-kv-cache-nvme-ssd-offload-explainer/5305417))构成同一趋势的两条技术路线:CXL 内存池做低延迟扩容、NVMe 做容量兜底。KV cache 正式成为独立于 HBM 的分层存储问题。
