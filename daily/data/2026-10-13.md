## 2️⃣ AI 编译器与框架
- **arXiv:简化 GPU kernel 的 layout 代数**:CuTe 那套 layout 操作(composition / complement / division / product)被至少六个互相耦合的"可采纳条件"约束,该文给出更简洁的形式化,直接降低写高性能 kernel 的门槛。[arXiv:2610.13679](https://arxiv.org/abs/2610.13679)
- **arXiv CompileMask**:现代 attention 需要运行时元数据决定的多样 mask,而高效 kernel 只原生支持少数模式;谓词法表达力强但预处理/执行开销大,该工作在编译期生成 mask 以同时要两点。[arXiv:2610.13474](https://arxiv.org/abs/2610.13474)
- **向量化 CLZ / CTZ**(HN 61 分):位运算原语在 SIMD 下的实现与陷阱,属于底层 kernel 写法的基础素材。[purplesyringa](https://purplesyringa.moe/blog/vectorized-clz-and-ctz/)
- **语言与形式化方向**:Clef 语言中状态服务的余指数(coeponential)建模与 delimited continuation;以及 RcCheck——把 Rust 语义纳入静态分析,同时覆盖资源死锁与通信死锁两类。[arXiv:2610.12911](https://arxiv.org/abs/2610.12911) / [arXiv:2401.01114](https://arxiv.org/abs/2401.01114)

## 3️⃣ AI 推理优化(数据中心)
- **arXiv:把 tokenization 从 host 卸载**:agentic 负载反复重发几乎不变的长上下文,prefix cache 已跳过大部分 prefill,**但每个请求仍要全量 tokenize** 才能查缓存——tokenize 于是变成 TTFT 的最大项,而前端 tokenizer 的吞吐直接限制了它能带多少张 GPU。[arXiv:2610.13325](https://arxiv.org/abs/2610.13325)
- **arXiv SlackSwap**:activation swap 到 host 内存的老前提(Titan X 时代 PCIe 带宽与算力大致匹配)已不成立,从 Titan X 到 H100 训练吞吐涨得远快于互联带宽,该文做带宽感知的换出与重计算联合调度。[arXiv:2610.13003](https://arxiv.org/abs/2610.13003)
- **NVIDIA 详解 GPT-6 Astra Ultrafast 的 GPU 加速**:基于 Blackwell 的推理优化做到最高 8 倍加速,已在 OpenAI API 与 ChatGPT Work/Codex 上线。[NVIDIA Blog](https://blogs.nvidia.com/blog/gpus-openai-gpt-6-astra-ultrafast/)
- **arXiv CacheScope**:training-free 的 diffusion 加速——一旦有了稳定的一阶重建器,继续堆重建复杂度收益有限,**"精确计算"放在哪几步**才是关键变量。[arXiv:2610.12530](https://arxiv.org/abs/2610.12530)
- **arXiv 代数整数量化(AINF)**:可直接归约到纯整数算术,实现无误差的 multiply-accumulate,并提供可预测误差界的矩阵乘引擎。[arXiv:2610.12494](https://arxiv.org/abs/2610.12494)
