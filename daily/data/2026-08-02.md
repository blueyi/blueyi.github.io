## 1️⃣ AI 芯片

- **[AMD MI450 上的 Attention Decode：Gluon Kernel 优化指南](https://rocm.blogs.amd.com/software-tools-optimization/gluon-attention-decode-mi450/README.html)**（HN 67 分）  
  AMD 官方 ROCm 博客发布了一篇面向 MI450 GPU 的 Attention Decode 算子优化实战指南，详细介绍了如何利用 Gluon 工具链对注意力解码阶段进行 Kernel 级调优。MI450 是 AMD 面向数据中心 AI 训练与推理的新一代加速卡（CDNA4 架构），这篇指南覆盖了从内存带宽瓶颈分析、Tile 大小选择、Wavefront 调度到寄存器压力平衡的完整优化流程，并给出了与 rocBLAS 默认实现的性能对比数据。对于在 AMD 生态上部署 LLM 推理的团队来说，这是一份非常实用的参考——毕竟 Attention Decode 是自回归生成的核心瓶颈。文章也侧面印证了 AMD 正在加大对 AI 软件栈的投入力度，试图缩小与 NVIDIA CUDA 生态在开发者体验上的差距。

## 2️⃣ AI 编译器与框架

- **[AMD MI450 上的 Gluon Kernel 优化指南](https://rocm.blogs.amd.com/software-tools-optimization/gluon-attention-decode-mi450/README.html)**（同上，HN 67 分）  
  Gluon 是 AMD 推出的高性能 Kernel 编写框架，定位类似于 NVIDIA 的 CUTLASS 或 OpenAI 的 Triton，但针对 AMD GPU 架构（CDNA/RDNA）进行了深度适配。这篇指南在编译器/框架层面的价值在于：它展示了如何用 Gluon 的声明式 API 描述 Attention Decode 的计算图，再由 Gluon 编译器自动生成优化的 HIP Kernel，大幅降低了手写汇编级优化的门槛。对于关注 MLIR/Triton/torch.compile 等技术路线的读者来说，Gluon 代表了另一种「高层描述 + 编译器自动生成高效 Kernel」的范式探索，值得持续追踪。

## 3️⃣ AI 推理优化（数据中心）

- **[探索性建模：在 K 个猜测中训练最优解](https://alexiglad.github.io/blog/2026/explorative_modeling/)**（HN 75 分）  
  这篇博客提出了一种新的训练范式：在每个训练步骤中生成 K 个候选输出（猜测），仅保留其中最优的一个用于梯度更新，其余丢弃。作者称之为"探索性建模"（Explorative Modeling），核心思想是将推理时的 Best-of-N 采样策略反哺到训练过程中，使模型学会在探索与利用之间取得平衡。虽然文章偏方法论而非系统实现，但其思路对数据中心级大模型训练的效率优化有启发意义——尤其是在强化学习微调（RLHF/GRPO）场景下，如何聪明地利用计算资源进行"探索"正在成为一个活跃的研究方向。

## 7️⃣ AI 自动算子与代码生成优化
