## 2️⃣ AI 编译器与框架

- **🔥 Google 让 PyTorch 原生跑上 TPU**:PyTorch 侧原生接入 TPU 后端,开发者不必再绕 XLA 专用路径,社区评价"早该如此"。对编译器栈的意义大于对硬件:此前 JAX/XLA 与 PyTorch 生态割裂是 TPU 最大的采用摩擦,打通后 TPU 与 GPU 的框架层差异被压缩到后端选择。[来源](https://www.infoq.cn/article/Fikt82HLToqb6ZANB2xj)
- **Relax:面向 Rust 的 JIT 编译器,专治构建慢**:Makepad 团队推出 Relax,用 JIT 思路削减 Rust 冗长的编译-链接周期(HN 101 分)。Rust 在 AI Infra 组件(vLLM、向量库、推理网关)中占比快速上升,编译时间已成工程效率瓶颈。[来源](https://makepad.github.io/relax/)
- **HuggingFace 发布 3D 生成模型微调权威指南**:系统梳理 3D LoRA 微调的数据构造、损失设计与显存取舍,把原本分散在论文里的经验固化为可复现流程。3D 资产生成正从 demo 走向可定制的生产工具链。[来源](https://huggingface.co/blog/3d-lora-finetuning)

## 3️⃣ AI 推理优化(数据中心)

- **存内计算重新被摆上推理主路径**:SemiEngineering 长文指出把计算搬到内存附近可同时降功耗、提带宽利用率,但软件栈、散热与架构一致性仍是三大障碍。在 HBM 容量与带宽成为推理第一瓶颈的当下,这是对"堆 HBM"路线的结构性挑战。[来源](https://semiengineering.com/rethinking-memory-for-ai-inference/)
- **FP8 格式系统科普(上):生态动能与硬件支持盘点**:从数值范围、动态范围折中讲到各厂商硬件支持矩阵。FP8 已是 Hopper/Blackwell 与国产 NPU 的事实标配,理解其舍入与 scaling 语义是量化部署的前置知识。[来源](https://semiengineering.com/introduction-to-fp8-formats-part-1/)
- **Google 发布首个「决策模型」Gemini Decision 1**:9 项测试拿下 7 项第一,最高准确率 92.2%。把"决策"从通用 LLM 的隐式能力拆成独立模型类别,意味着 agent 编排层的推理开销可能被专用小模型接管,而不是每步都调大模型。[来源](https://www.infoq.cn/article/E7QKIMUz3h0G0IE5Paii)
- **TPU 8i Max 把推理带宽翻倍(见 1️⃣)**:硬件层面的直接回应是——decode 阶段的瓶颈在 KV Cache 读写而非算力,带宽翻倍比 FLOPS 提升更能改善 tokens/s/美元。[来源](https://www.servethehome.com/google-tpu-8tx-8i-max-amd-epyc-turin/)
