# 📡 AI Infra 日报 · 2026-07-14(周二)

## 1️⃣ AI 芯片
- [StreamDQ:自定义 HBM 内近存权重反量化](https://arxiv.org/abs/2607.08993)(cs.AR):指出当前 GPU 上 CUDA core 反量化带来指令开销、片上流量与流水线阻塞,是高吞吐推理的主要瓶颈;方案把反量化下沉到定制 HBM 近存单元,面向可扩展 AI 推理加速,是"存算靠近"路线在权重量化场景的一次硬件级尝试。
- [LLM for EDA 前端设计:挑战与机遇](https://arxiv.org/abs/2607.09616)(cs.AR):随着芯片复杂度上升、上市压力增大,前端设计成为瓶颈;综述 LLM 在电子设计自动化(EDA)中作为统一智能接口的潜力,涵盖规格理解、HDL 生成与测试(与第 7 类交叉)。
- 背景:本窗口无 Nvidia/AMD/TSMC/SK Hynix 等厂商的独立新品或制程动态,以上为学术侧信号。

## 2️⃣ AI 编译器与框架
- [黑盒场景下推断大语言的准确上下文无关文法](https://arxiv.org/abs/2607.08959)(cs.PL):针对 Arvada、TreeVada、Kedavra 等在大型语言上可扩展性/准确性/可读性不足的问题,Xvada 引入确定性推断新技术;对程序分析、逆向、模糊测试等编译前端工具链有直接价值。
- [Bidirectional Elaborators à la Carte](https://arxiv.org/abs/2607.09564)(cs.PL):面向 Rocq/Lean/Agda/Idris 的隐式表层语法,系统化研究把表层语法翻译为显式核心语法的 elaboration 算法的可靠性与可预测性——证明助手/DSL 编译器的地基工作。
- 背景:tinygrad / MLIR / TVM / Triton / torch.compile 本窗口无重大独立发布;以上为 PL 侧的编译前端进展。

## 3️⃣ AI 推理优化(数据中心)
- [SiFAR:面向低延迟 LLM 推理的无同步 All-Reduce](https://arxiv.org/abs/2607.08973)(cs.DC):推理模型与 agentic 系统产生大量不被人类阅读的中间推理 token,per-token 延迟直接决定端到端时延;低延迟推理用极小 batch,使 token 生成受带宽制约,SiFAR 以去同步化的 All-Reduce 缓解通信瓶颈。
- [Director:在线主动专家放置加速分布式 MoE 服务](https://arxiv.org/abs/2607.08782)(cs.LG):专家并行下效率取决于专家在 GPU 上的放置;现有方法依赖历史激活模式,面对多样负载能力不足,Director 以在线主动放置应对。
- [用中等非结构化稀疏权重矩阵加速 GPU LLM 推理](https://arxiv.org/abs/2607.08786)(cs.AR):为保模型质量,剪枝通常止步于约 50% 非结构化稀疏,而此稀疏度下现有 GPU 稀疏矩乘 kernel 均无收益;工作面向这一"中等稀疏"空档做加速。
- [Signed Symmetric Quantization:少比特整数的符号对称量化](https://arxiv.org/abs/2607.08779)(cs.LG):有符号整数负端比正端多一个可表示值,传统对称量化把它划给负尾,导致正向离群值被裁剪;在少比特精度下这类裁剪是非平凡的量化误差来源(与第 8 类交叉)。

## 4️⃣ 数据中心与基础设施
- [面向解耦异步 RL 后训练的双向资源调度](https://arxiv.org/abs/2607.09207)(cs.DC):RL 后训练中 policy 通过 rollout 生成经验再更新,StreamRL/AReaL 等高性能框架存在资源利用不均;工作提出双向资源调度,平衡生成与训练两侧算力——大规模 RL 训练集群的调度优化。
- [EcoKube:异构边缘-云环境下碳感知调度策略仿真](https://arxiv.org/abs/2607.09318)(cs.DC):在混合边云场景下,可持续性受时空变化的电网碳强度(CI)、站点 PUE 与异构硬件影响;EcoKube 提供碳感知调度策略的仿真环境,对接超大规模数据中心的电力与碳排治理。
- [超曲随机图上的分布式对称破缺](https://arxiv.org/abs/2607.09170)(cs.DC):以超曲随机图(HRG)刻画互联网等真实网络的幂律度分布与高聚类特性,解释了为何部分算法在真实网络上优于最坏情况——分布式系统理论侧背景性成果。

## 5️⃣ AI 安全与治理
- 🔥 [GhostLock:潜伏 15 年、覆盖所有 Linux 发行版的栈 UAF](https://nebusec.ai/research/ionstack-part-2/)(HN 392 分):影响面覆盖全部 Linux 发行版的栈上 Use-After-Free 漏洞,存在时间长达 15 年;对承载 AI 集群的底层操作系统安全构成系统性风险,值得基础设施团队关注补丁进展。
- 🔥 [Zig 作者直言不讳,Anthropic 在放烟雾](https://raymyers.org/post/zed-creator-calls-spade-a-spade/)(HN 1399 分):围绕 Anthropic 相关表述的公开质疑成为社区高热话题,折射 AI 大厂"营销叙事 vs 工程实质"的治理与信任议题。
- [从交互视角统一解读大模型的知识蒸馏](https://arxiv.org/abs/2607.08776)(cs.LG):把 LLM 输出得分分解为大量"交互"之和,统一解释各类 KD 方法的共同机制——提升蒸馏可解释性,属对齐/可解释性方向。
- [Ceci n'est pas une pipe:将 AI 系统视为语义抽象](https://arxiv.org/abs/2607.09489)(cs.PL):主张 AI 输出并非其所描述的世界状态,而是被工程化的表示;提出语义框架区分"领域知识所证成""参考源所述""系统当前所用",以检验表示的正确性——AI 系统正确性治理的理论工具。

## 6️⃣ 具身智能
- [CLAP:通过语言-动作对齐实现 VLM 到 VLA 的直接适配](https://arxiv.org/abs/2607.08974)(cs.RO):VLA 继承预训练 VLM 的语义能力,但大规模机器人数据后训练与架构改动常重塑 backbone,难以厘清 VLM 的贡献;CLAP 以最小架构改动直接转化 VLM,提供更透明的控制路径。
- [AgenticFocus:从人类第一视角视频合成保物体的混合现实数据](https://arxiv.org/abs/2607.08857)(cs.RO):将普通 FPV 人类视频转为可训练机器人示范,解决手-物遮挡、运动过简与专用采集硬件依赖,为人形策略学习提供可扩展监督源。
- [FlowDAgger:潜空间中人在回路的生成式机器人策略适配](https://arxiv.org/abs/2607.08877)(cs.RO):针对 flow matching/扩散预训练策略在真实部署中暴露的分布外失效,以潜空间人在回路适配替代昂贵的大规模数据采集或在线 RL。
- [SplatCtrl:高斯场景表征驱动的感知-动作耦合与反应式控制](https://arxiv.org/abs/2607.08948)(cs.RO):基于 3D 高斯泼溅实现实时场景重建与反应式运动生成,在未见且持续变化的环境中做无碰撞机械臂控制。
- [BeyondSight:端到端自动驾驶的物体恒存性](https://arxiv.org/abs/2607.09138)(cs.RO):多数端到端驾驶把"目标存在"耦合到瞬时观测,长时遮挡会使目标假设退化;工作为遮挡下的关键 agent 引入物体恒存能力。
- 另有 [Dec-MARVEL 无通信多机探索](https://arxiv.org/abs/2607.09060)、[血管几何表征辅助血管内导航](https://arxiv.org/abs/2607.09130)、[BLDC 电机残差 PINN 建模](https://arxiv.org/abs/2607.09136) 三篇机器人子方向工作。

## 7️⃣ AI 自动算子与代码生成优化
- [LLM for EDA 前端设计](https://arxiv.org/abs/2607.09616)(cs.AR,与第 1 类交叉):重点在 LLM 作为统一接口做 HDL/RTL 生成与测试生成,是"LLM 写硬件描述语言"的系统性综述。
- [黑盒文法推断 Xvada](https://arxiv.org/abs/2607.08959)(cs.PL,与第 2 类交叉):确定性文法推断可服务于自动化程序理解与模糊测试的代码生成环节。
- 背景:AlphaEvolve / FunSearch / AI Kernel 自动生成本窗口无独立发布;当前信号集中在 LLM 驱动的 RTL/程序结构生成学术侧。

## 8️⃣ 边缘与端侧推理
- [STEEL:面向 AMD XDNA NPU 的稀疏感知融合注意力](https://arxiv.org/abs/2607.09385)(cs.AR):随 OS 工作流中 LLM agent 普及,笔记本级 SoC 上的能效推理愈发重要;云卸载带来可靠性与隐私隐患(对 agentic 负载尤甚),STEEL 在新一代笔记本 NPU 上做能效长序列推理——端侧 agent 落地的关键路径。
- [Sticky Routing:训练面向内存高效推理的 MoE 模型](https://arxiv.org/abs/2607.08780)(cs.LG):边缘设备上相邻 token 常激活不同专家,导致权重在慢存储与快内存间反复换入换出;现有缓存启发式/事后路由微调未触及根因,Sticky Routing 从预训练阶段改造路由行为。
- [Signed Symmetric Quantization](https://arxiv.org/abs/2607.08779)(cs.LG,与第 3 类交叉):少比特量化的符号对称改进,对端侧 INT4/W4A16 等极低比特部署有直接意义。
- [电动车电池功率的端侧自适应预测](https://arxiv.org/abs/2607.09400)(cs.AR):在资源受限 EV 上做 on-device 学习以应对分布漂移——虽非 LLM,但代表端侧自适应推理的工程范式。

1. **端侧 agent 推理成为独立主线**:STEEL(AMD XDNA NPU)与 Sticky Routing(MoE 权重换入换出)同日出现,共同指向"把 agentic 负载从云拉回笔记本/NPU"以规避隐私与可靠性风险,少比特量化(Signed Symmetric)则是配套弹药。
2. **数据中心侧围绕"低延迟"与"RL 后训练"发力**:SiFAR 无同步 All-Reduce 直击推理模型中间 token 的 per-token 延迟,Director 优化 MoE 专家放置,双向资源调度平衡 RL rollout 与训练两侧算力。
3. 🔥 **GhostLock(HN 392)**:潜伏 15 年、覆盖全部 Linux 发行版的栈 UAF,是承载 AI 集群底座 OS 的系统性安全隐患,基础设施团队应跟进补丁。
4. 🔥 **Anthropic 争议登顶 HN(1399 分)**:"营销叙事 vs 工程实质"的信任议题发酵,是当前 AI 大厂治理层面最受关注的社区信号。
5. **具身智能持续密集**:CLAP 探索 VLM→VLA 的透明适配路径,AgenticFocus/FlowDAgger 分别从数据合成与人在回路两端降低真机部署成本,VLA 正加速走向可复现。
