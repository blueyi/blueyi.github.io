## 2️⃣ AI 编译器与框架

- **用 E-Graph 自动检查编译器正确性**:文章给出把优化规则编码为 e-graph 重写、再用等价性检查证明其保持语义的方法,把"编译优化引入 bug"从靠测试抽样变成可机械化验证。对自研编译器/DSL 团队,这是比差分测试更强的门禁手段。[Substack](https://stng.substack.com/p/automatic-checking-of-compiler-correctness) · [HN 63 分](https://news.ycombinator.com/item?id=50537492)
- **MetaphIR:语料级分析 LLVM Peephole 优化的实际收益**:针对每条 peephole 规则统计真实程序里"匹配模式且满足前置条件"的频率,让编译器开发者在下手写重写规则前就知道它值不值得维护。这类"优化器收益测量"工具是编译器工程长期缺失的一环。[arXiv 2611.23555](https://arxiv.org/abs/2611.23555)
- **HEL:GPU 常驻运行时的服务化编排**:把任务当作协程式协程交给常驻 GPU 的 runtime 调度,支持同步/异步任务、运行时依赖、批量提交与自动资源管理。相比 host 侧反复 launch,这类 GPU-resident runtime 是降低小算子调度开销的一条路径。[arXiv 2610.24830](https://arxiv.org/abs/2610.24830)
- **不改 HLS 编译器也能吃到 FPGA 硬核**:用 C++ 模板库固定源码模式、由自动流程挑选调度设置,直接生成 DSP/BRAM 等硬核的原生实现,避免 HLS 把硬核重建到 fabric 上浪费面积与时序。对边缘 FPGA 加速器的面积预算意义直接。[arXiv 2611.25281](https://arxiv.org/abs/2611.25281)

## 3️⃣ AI 推理优化(数据中心)

- **Twindex:长上下文稀疏注意力的 index cache 卸载**:论文指出主 KV 一旦下沉到 host 内存,indexer cache 就成了新的 HBM 占用大户(每个 decode step 都要给全部历史 index entry 打分),于是用粗到细的选择策略把 index cache 也做分级卸载。这是 sparse-attention serving(DeepSeek/GLM/Qwen 系)在长上下文下的真实内存账本。[arXiv 2611.25078](https://arxiv.org/abs/2611.25078)
- **TripleKV:为 Agent 负载做 KV 预测—预取—保护**:Agent 在推理与工具执行之间反复切换,并发下 KV 工作集可达数百 GiB,块被换出后返回时检索代价极高。论文用访问模式预测提前预取并保护关键块,直指 agent 类负载与传统 chat serving 的调度差异。[arXiv 2611.25112](https://arxiv.org/abs/2611.25112)
- **Berth:不做新抢占也能保住 SLO 的 GPU 共享**:推理服务按峰值预留 GPU 导致大量空转,填训练任务又会被毫秒级延迟请求卡住。论文在既有抢占语义之外重新组织空间/时间共享,给出"填谷但不违约"的调度方案,直接对应推理集群利用率这个最贵的指标。[arXiv 2611.25091](https://arxiv.org/abs/2611.25091)
- **高带宽 Flash(HBF)用于 LLM serving 的定量刻画**:论文实测 HBF 的访问代价与写入寿命上限,评估把权重与 KV cache 放到 flash 层扩容器量的真实收益边界。在 HBM 容量成为 agent 负载硬约束的当下,这类"下一层内存到底值不值"的实测比架构 PPT 有用。[arXiv 2609.39131](https://arxiv.org/abs/2609.39131)
- **180B MoE 塞进 32GB 内存:Transformers 侧的 expert streaming**:HuggingFace 博文展示按专家流式加载把超大 MoE 跑在单机小内存上,代价是 PCIe 带宽换容量。对没有 H100 集群但想验证 MoE 行为的团队,这是可复现的低成本路径。[HuggingFace](https://huggingface.co/blog/moe-expert-streaming)

## 7️⃣ AI 自动算子与代码生成优化

- **🔥 Claude 解决黑洞物理两个开放问题,数学家又宣称用它证出黎曼猜想**:Anthropic 研究页展示 Claude 在黑洞物理中解决两个公开问题(559 分热帖);同日其研究员 Levent Alpöge 宣称与 Claude 合作得到黎曼猜想的证明,仅发布 Lean 代码,陶哲轩表示验证仍需时间。无论最终验证结果如何,"LLM 产出可机检形式化证明"已经把 AI 的代码生成能力推到数学研究的生产线上。[Anthropic](https://www.anthropic.com/research/claude-black-hole-physics) · [HN 551 分](https://news.ycombinator.com/item?id=50563148) · [IT之家](https://www.ithome.com/1/030/297.htm)
- **KernelOPT:面向 GPU kernel 优化的调度感知 agentic 搜索**:指出 PyTorch Inductor 自动生成的 kernel 常大幅落后手写实现,而现有 LLM 优化器只在孤立 kernel 上打磨、忽略调度与真实负载。论文把搜索空间与 dispatch 条件绑定,是 AI 写 kernel 从"刷 benchmark"走向"能上生产"的关键一步。[arXiv 2609.30059](https://arxiv.org/abs/2609.30059)
- **DVBench:面向真实 UVM 验证流程的端到端 agent 基准**:现有基准把验证拆成互相解耦的子任务,偏离实际 UVM 工程。该基准以完整验证流程评测 LLM agent,把"AI 写 RTL/写验证"的评测从玩具题拉向工业流程。[arXiv 2611.25066](https://arxiv.org/abs/2611.25066)
- **Trace2ST:用 LLM 从 I/O 轨迹恢复 PLC 结构化文本程序**:针对源码已丢失、但输入输出被持续记录的工业控制器,让 LLM 生成可执行的 ST 程序并用验证闭环纠错。这是 LLM 代码生成在"无源码遗留系统"上的实用切口。[arXiv 2611.24979](https://arxiv.org/abs/2611.24979)
- **PDD Kit:为 agent 写的全栈 Web 应用做形式化验证**:把开发者意图转成 Verus 规约并证明 AI 生成代码满足规约,应对"agent 生成代码量超出人类逐行审阅能力"的现实。对把 agent 引入生产流水线的团队,这是补齐评审环节的一条正经路径。[Microsoft Research](https://www.microsoft.com/en-us/research/blog/formally-verifying-agent-written-full-stack-web-apps-with-pdd-kit/)
