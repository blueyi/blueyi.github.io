## 1️⃣ AI 芯片

- [Nvidia DGX Spark 当日常主力机是什么体验](https://daniel.lawrence.lu/blog/2026-07-15-dgx-spark-as-daily-driver/)(HN 81 分)— 开发者长期实测 GB10 平台的 DGX Spark:128GB 统一内存跑本地大模型很香,但 ARM 生态兼容性、内存带宽瓶颈仍是日用痛点,是一手的小型 AI 工作站体验报告。
- [非结构化流体力学上片上数据流架构:代码与数据联合分解](https://arxiv.org/abs/2607.18650) — 面向 Cerebras 类空间数据流(Spatial Dataflow)硬件,解决非结构化网格的间接访存与高维通信映射问题,拓展了这类固定内存 PE 阵列芯片的适用边界。
- [Mapping Without Graphs:学习缓存一致性流量做任务放置](https://arxiv.org/abs/2607.18879) — 摆脱预定义任务图,直接从 NoC 一致性流量中学习通信模式来做众核任务映射,属于多核芯片系统级优化。
- [PIP-NTT:面向后量子密码的可扩展内存并行 NTT 加速器](https://arxiv.org/abs/2607.18533) — 改进迭代 NTT 的乒乓存储方案,降低对大块存储的依赖;同场加映一篇[乱序多核对弱内存 ISA 的形式化验证](https://arxiv.org/abs/2607.18727),硬件正确性方向。

## 2️⃣ AI 编译器与框架

- [面向 MLIR 的 Schema 派生约束解码:免重训跨方言泛化](https://arxiv.org/abs/2607.18254) — MLIR 在预训练语料中几乎绝迹且方言无限扩展,per-dialect 微调不可持续;本文用从 ODS schema 机械推导的推理期先验做约束解码,让 LLM 免重训生成新方言 IR,对 ML 编译器工具链自动化意义直接。
- [带可见性控制的高效流水线高层次综合(HLS)](https://arxiv.org/abs/2607.18765) — 在 HLS 中引入细粒度流水线结构与冒险消解控制,兼顾抽象层次与 PPA,补上现有工具"要么没控制、要么牺牲抽象"的短板。
- [Build-Authorized Evidence:不透明调用的失效关闭重写边界](https://arxiv.org/abs/2607.18949) — 讨论编译器对不透明 native provider 做语义重写时的授权边界,fail-closed 设计对链接原生算子库的 ML 编译器同样有借鉴意义。
- LLM 直接生成 RTL 的渐进式规范化方法见第 7️⃣ 类,同样属于"编译器 + 生成式"交叉。

## 3️⃣ AI 推理优化(数据中心)

- [moefs:感知"可构建性"的 MoE 训练/推理全空间优化器](https://arxiv.org/abs/2607.18631) — 指出自动并行优化器常给出"成本模型上最优、工具链却编不出来"的方案,moefs 把 realizability 显式纳入搜索,是 MoE 系统部署的实用痛点。
- [InstantInfer:用通信有限自动机加速 LLM 冷启动](https://arxiv.org/abs/2607.18957) — 针对推理服务冷启动的串行初始化与海量细粒度 I/O,以自动机形式化改写实现并发执行与 I/O 合并,serverless LLM 场景直接受益。
- [复合稀疏前沿:静态剪枝 × 动态 token 稀疏的组合压缩](https://arxiv.org/abs/2607.18280) — 研究两类稀疏机制联合分摊压缩负担,能否推迟单一稀疏化的"性能悬崖",给出 LLM 复合稀疏的边界刻画。
- [是什么决定了 GPU LZ77 绝对偏移格式的解码吞吐](https://arxiv.org/abs/2607.18541) — 在 H100 上做受控消融,提出工作粒度机制与编码期 min-match-length 调节杆,GPU 压缩驻留数据的解码优化对大规模数据管线有参考价值;另有 [PRISM:面向同态加密推理的多项式敏感度感知剪枝](https://arxiv.org/abs/2607.18342),密态推理方向一笔带过。

## 7️⃣ AI 自动算子与代码生成优化

- [用 LLM 渐进式生成可综合 RTL 设计](https://arxiv.org/abs/2607.18519) — 指出 LLM 写 Verilog 的失败多源于对非正式规范的"静默误读",提出渐进式方法把模型的规范理解显式化后再落码,LLM 硬件设计生成的关键补丁。
- [Decode-Time Grammars:按语法片段精化序做约束生成](https://arxiv.org/abs/2607.18357) — 面向 DSL、私有库 API、CLI 等低资源编程面,在解码期施加可精化的语法约束,让 agent 无人工审查执行生成代码更可靠。
- [VirtualSet:以类型化本体世界替代 SQL 作为 LLM 生成目标](https://arxiv.org/abs/2607.18821) — SQL 报错太晚、幻觉字段能跑出貌似合理的错答案;改为接收方定型的集合表达式,提前拦截错误、护栏写操作。
- 前述 [MLIR 约束解码](https://arxiv.org/abs/2607.18254) 同属"LLM 驱动编译器"路线,证明推理期结构先验可替代 per-dialect 微调。
