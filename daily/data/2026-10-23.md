## 2️⃣ AI 编译器与框架
- **MXFP4 点积中的 scale 放置位置可以判定**：把 shared scale 放在 reduction 之前还是之后，在实数域中两者等价，但在 binary32 下会因上溢/下溢产生不同结果；论文用整数运算给出了可判定的策略，这属于编译器 lowering 中一个实际的安全边界。[arXiv 2610.29445](https://arxiv.org/abs/2610.29445)
- **Operon：用命名维度增量构建 ragged 数据**：针对内层长度要到运行时才可知的多维集合，抛弃嵌套容器表示，恢复形状语义与任务依赖可见性；这适用于数据流水线和工作流引擎。[arXiv 2511.16080](https://arxiv.org/abs/2511.16080)
- **MockingBird：上下文感知的仓库级代码翻译与隔离验证**：它结合了按源文件检索 API 文档与上下文、跨类型系统的类型解析，并用 mock 做隔离的功能等价校验。[arXiv 2511.21878](https://arxiv.org/abs/2511.21878)
- **Hugging Face 原生支持 TorchTPU**：TPU 从“需要另行接入”变成框架的一等后端，对 JAX/PyTorch 双栈团队是个信号。[HuggingFace Blog](https://huggingface.co/blog/hf-torchtpu)

## 3️⃣ AI 推理优化(数据中心)
- **RISK-KV：质量感知的选择性 KV 重建**：在分布式推理的请求迁移与中断恢复中，不搬运整份 cache，而按质量要求选择性重建历史 KV，以在状态开销与重放计算之间取平衡。[arXiv 2610.29544](https://arxiv.org/abs/2610.29544)
- **UlaCache：统一逻辑地址空间做稀疏 LLM 服务**：在 GPU KV pool 与更下层存储之间建立统一编址，使稀疏注意力保留的 KV 在后续 decode 步依然可寻址。[arXiv 2610.29820](https://arxiv.org/abs/2610.29820)
- **“留还是不留”：分离式服务中的 KV 保留策略学习**：在 prefill/decode 分离后，cache miss 不再只是本地重算，还叠加了到 decode 节点的网络传输；准入与保留变成需要学习的联合决策。[arXiv 2610.28637](https://arxiv.org/abs/2610.28637)
- **HAWK：GPU-NPU 异构相位分离的 KV 传输**：GPU 擅长 prefill、NPU 在 decode 阶段利用率更高，论文针对两者间 KV 搬运的异构性做了专门优化。[arXiv 2610.29873](https://arxiv.org/abs/2610.29873)
- **CARDAN：AWS Trainium 上的 MoE 解码多引擎数据流**：把专家权重矩阵表示为向量量化分量，缓解“只有搬运专家权重时才会隐藏”的流量瓶颈。[arXiv 2609.21137](https://arxiv.org/abs/2609.21137)
- **OpenAI 全面开放 Decisions API**🔥：基于 GPT-6 Luna，把模型能力限制在有界答案的问题上，响应速度比通过 Responses API 调用提升最多 10×，每百万输入 token 仅 $0.1；“决策”正被拆成独立于生成的一类推理产品。[IT之家](https://www.ithome.com/1/016/771.htm)
