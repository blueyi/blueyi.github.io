## 2️⃣ AI 编译器与框架

- **KL 散度在数学上不为负，PyTorch 里出现了例外**：HN 83 分，指向 arXiv 论文《The KL Divergence Is Never Negative, Except in PyTorch》。KL 散度被用作蒸馏、对齐和正则时，一旦被算成负数，优化器会把本应惩罚的方向当成奖励，而且这种错误不会写在模型卡上。讨论来自 Hacker News。[来源](https://arxiv.org/abs/2611.30835)
- **微调为什么比 FLOPs 算出来的更慢**：Hugging Face 这篇的标题就是结论：真实微调时长会长于按浮点运算估算的时间。按峰值算力去除模型 FLOPs，会把数据加载、同步和状态搬运当成零，工期和单价都会偏乐观。[来源](https://huggingface.co/blog/Dharma-AI/predicting-fine-tuning-time)
- **用前沿模型加 Omniverse 把仿真从想法收成应用**：NVIDIA 博客描述，把一个仿真想法做成能跑的应用，意味着组装资产、接上物理和渲染、再检查场景是否符合预期。开发者正在把前沿模型与 Omniverse 合在一起做这些步骤。框架层把场景搭建从手工管线变成模型可调用的步骤，具身和科学仿真缺的往往是这层胶水。[来源](https://blogs.nvidia.com/blog/developers-simulation-frontier-ai-agents/)

- **复杂记忆甚至跑不过原始 RAG，UIUC 等提出「记忆税」**：新智元报道了这一说法。摘要把记忆定义成对历史的有偏重构：无论人脑还是长周期智能体，一旦建立记忆，原始交互就会被提炼、合并、更新和遗忘，重新编成不同层级。标题指向一个反直觉结论：更复杂的记忆未必赢过直接检索原文。智能体的推理成本不能只按生成 token 计，记忆的写入、合并和召回是一笔不一定买来正确率的开销。[来源](https://aiera.com.cn/2026/11/24/other/admin/125031/%e6%99%ba%e8%83%bd%e4%bd%93%e5%a4%8d%e6%9d%82%e8%ae%b0%e5%bf%86%e7%94%9a%e8%87%b3%e8%b7%91%e4%b8%8d%e8%bf%87%e5%8e%9f%e5%a7%8brag%ef%bc%9fuiuc%e7%ad%89%e9%a6%96%e6%8f%90%e3%80%8c%e8%ae%b0%e5%bf%86/)
- **「缓存税」被拿来解释 Anthropic 的利润结构**：新智元援引开发者圈讨论，发帖者包括 Java Champion Vlad Mihalcea，把提示缓存计费称作 Anthropic 的「缓存税」。推理优化过去把缓存当成纯技术胜利：命中前缀就能少算。一旦命中本身成为定价项，命中率上升、算力下降，账单却未必下降。优化目标会从少算 FLOPs 改成在计费规则下少付钱。[来源](https://aiera.com.cn/2026/11/24/other/admin/125064/%e6%8f%ad%e7%a7%98anthropic%e7%9a%84%e3%80%8c%e6%9a%b4%e5%88%a9%e3%80%8d%e7%9c%9f%e7%9b%b8%ef%bc%9a%e7%bc%93%e5%ad%98%e7%a8%8e%ef%bc%81/)
- **杰文斯悖论：更便宜的 token 付不起资本开支**：HN 79 分。文章标题直接否定「降价就能做大用量、用量就能覆盖机房资本开支」这条链条。量化、缓存和投机解码都在把单 token 成本往下打；若用量放大填不上已签约的电力和 GPU，便宜本身会变成收入缺口。[来源](https://philippdubach.com/posts/cheaper-ai-tokens-wont-pay-for-capex/)
