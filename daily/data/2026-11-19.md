## 3️⃣ AI 推理优化(数据中心)
- **TAILROLL:按“长尾”而非“均值”调度 RL rollout**:RL 后训练的真正瓶颈是重尾响应——每步都在等最长那条样本,异步训练只能掩盖不能消除空转;该工作把失衡浪费(放置不均、decode 争用)与掉队浪费分开建模,据尾部长度而非平均负载做调度。[arXiv cs.DC](https://arxiv.org/abs/2611.22206)
- **XM-Sparse:把稀疏注意力的全量 KV 搬到 scale-up 内存池**:生产级长上下文模型即便用稀疏注意力仍需保留完整 KV 历史,HBM 容量直接锁死并发;方案绕开 PCIe 带宽与主机内存容量双重瓶颈,依托 X-Mem 一类 scale-up 内存池做高吞吐服务。[arXiv cs.DC](https://arxiv.org/abs/2611.22280)
- **SpecSearch:推测解码的配置必须随硬件与并发自适应**:同一 drafter 在 RTX 5090 低并发下可达 3.50× 吞吐,高并发却掉到 0.76×(不如自回归);论文把 draft 长度、显存预算与工作负载联合搜索,做硬件感知的 SD 配置。[arXiv cs.DC](https://arxiv.org/abs/2611.22296)
- **MoE 专家并行:压缩“变化量”而非激活本身**:MoE 每层两次同步集合通信(dispatch/combine)是大规模推理的主要开销,论文用激活压缩削减跨设备搬运字节,在保持精度的前提下提升专家并行效率。[arXiv cs.DC](https://arxiv.org/abs/2611.22215)
- **180B 参数跑在 32GB 内存:Transformers 侧 MoE 专家流式加载**:不改框架、以专家为粒度按需换入,让超大 MoE 在单机小内存上可跑——牺牲延迟换容量,是低成本验证与端侧/单机部署的实用折中。[HF Blog](https://huggingface.co/blog/moe-expert-streaming)

## 7️⃣ AI 自动算子与代码生成优化
- **🔥 OpenAI 模型参与真实芯片设计:Jalapeño 硅片电路优化 + RISC-V 核心改进**:官方称模型对 Jalapeño 硅片所用电路做了优化,并改进了 RISC-V 核心设计(HN 147 分),把“LLM 写 RTL/做电路优化”从 demo 推到流片相关环节。[OpenAI](https://openai.com/index/advancing-chip-design-with-our-models/)
- **RTLReviewBench:LLM 硬件评审几乎不漏 bug,却常误杀正确 RTL**:114 对“同规格、一对一错”的 Verilog 模块测试显示,模型在不仿真前提下极少漏掉缺陷,但对正确模块的误拒率很高——直接用作门禁会把正确设计挡在流程外,更适合当高召回预筛。[arXiv cs.AR](https://arxiv.org/abs/2611.21678)
- **Warpline:给 agent 装上 warp 级二进制追踪**:现有 profiler 只报单元繁忙度、手工插桩又要重编译从而改变被测内核;该工作免改代码给出每个 warp 的时间去向,让 LLM agent 做 GPU kernel 优化时有真实证据链。[arXiv cs.PL](https://arxiv.org/abs/2611.04331)
- **KD-DSE:知识驱动的 LLM 微架构设计空间探索**:针对“每个候选都要全量仿真、代理模型需上千次仿真才可信、LLM agent 又会幻觉”的三重困境,用冷启动架构知识 + 自适应策略替代固定每轮策略。[arXiv cs.AR](https://arxiv.org/abs/2611.22411)
