## 3️⃣ AI 推理优化(数据中心)

- 🔥 [GPT-5.5 Codex reasoning-token clustering may be leading to degraded performance](https://github.com/openai/codex/issues/30364)(HN **354** 分)—— OpenAI `codex` 仓库出现的这条 issue 在 HN 引爆讨论。核心怀疑:GPT-5.5 Codex 在服务端做 **reasoning-token 聚簇/批处理**(把多个用户会话的 CoT token 拼到同一个 batch 或复用同一段中间状态)以摊薄推理成本,但在高并发下引入了跨请求的隐式耦合,导致 **同一 prompt 在不同时段/负载下输出稳定性显著下降**、代码补全质量出现肉眼可见的波动。对推理系统的启示是明确的:continuous batching + reasoning-model 的组合并不是"免费午餐"——当中间推理 token 占比远高于最终输出 token 时,batch 内 token 分布的方差会被放大,PagedAttention/prefix cache 的命中策略、乃至 speculative decoding 的接受率都可能被拖累。vLLM / SGLang / TensorRT-LLM 阵营接下来需要重点回答:**reasoning model 的 batching 边界应该画在哪里,是否需要为 CoT 段单独开辟隔离的 KV 分片**。这也是继上半年"long-context 下 prefix cache 失效"讨论之后,推理侧最值得追的架构级问题。

## 5️⃣ AI 安全与治理

- 🔥 [EU Council forces Chat Control via fast-track](https://www.heise.de/en/news/Chat-Control-1-0-EU-Council-forces-messenger-scans-via-fast-track-11353659.html)(HN **384** 分)—— 欧盟理事会通过"快速通道"程序强推 **Chat Control 1.0**,要求消息类应用(WhatsApp、Signal、iMessage、Telegram 等)对用户内容进行 **客户端扫描 (client-side scanning, CSS)**,以 CSAM(儿童性剥削材料)检测为名义,在端到端加密之外插入一层强制的本地哈希/AI 匹配。对 AI Infra 与治理层面的三重冲击:**(1) 端侧 AI 被首次以立法形式"征用"** —— 手机上的 NPU 将被迫承载政府指定的分类/哈希模型,厂商 (Apple / Google / Meta) 是否配合、模型是否可审计、误报率如何披露,将成为接下来数月的核心争议;**(2) 端到端加密的政策终局** —— Signal 已多次表态"宁可退出欧盟市场也不接入 CSS",Chat Control 1.0 若正式生效,可能触发主流加密通讯应用的欧盟撤出潮;**(3) AI 分类器的合规责任链** —— 一旦模型误报导致公民被误判,责任归属(模型提供方 / 应用厂商 / 成员国政府)在现行框架下完全模糊。这是欧盟继 AI Act 之后对 AI 治理格局影响最大的一次立法动作,量级远超一般政策新闻,值得所有做端侧模型、隐私推理、以及跨国 AI 产品的团队立即评估影响面。

## 6️⃣ 具身智能

- [Autonomous flying umbrella follows and shields users from rain and sunlight](https://www.designboom.com/technology/autonomous-flying-umbrella-follows-users-rain-sunlight-i-build-stuff-01-13-2026/)(HN **89** 分)—— 一款可 **自主跟随人体、遮挡雨水与阳光** 的飞行伞原型登上 HN 前排。虽然本质更接近 DIY hobbyist 项目而非产业级具身智能,但从技术栈看却完整覆盖了 **感知—定位—控制** 三段:视觉/雷达跟踪人体、SLAM 维持相对位姿、姿态控制在动态风场下保持稳定悬停。这类"贴身跟随无人机"过去几年最大的瓶颈从来不是硬件,而是 **户外强扰动下的鲁棒策略** —— 树影、逆光、突风、周围行人干扰都会让传统 PID/MPC 失效。若后续能引入学习型策略(RL 或 Diffusion Policy 替代手写控制律)甚至端侧 VLA 模型进行意图理解(判断"用户想避雨"还是"用户想拍照"),就有机会从玩具走向消费级产品。人形机器人之外,**"随身漂浮设备"** 或将成为具身智能下一个被忽视但有实用价值的细分方向。
- [Airplane Boneyards List and Map](https://airplaneboneyards.com/airplane-boneyards-list-and-map.htm)(HN **81** 分)—— 严格意义上是航空退役场地数据聚合站,与具身智能无直接关联,但对 **自动驾驶/无人机的仿真数据采集** 而言是一份意外的资源清单:全球飞机坟场是极佳的 **大规模、静态、可控光照的开放场景**,适合做 LiDAR / 多视图重建 / NeRF-Sim 训练数据,历史上已有多支 CV/机器人团队在类似环境采集数据。作为背景资料保留。

## 8️⃣ 边缘与端侧推理

近两天无重大独立动态,但值得关注一条 **政策倒逼技术** 的信号:第 5 类中提到的 **EU Chat Control 1.0**(HN 384 分)一旦落地,将直接把端侧 AI 推理推到监管前台。所有主流手机厂商都会被要求在 **本地 NPU (Apple ANE / Snapdragon Hexagon / MediaTek APU)** 上持续运行分类模型,这意味着 **llama.cpp / MLC-LLM / ExecuTorch / MLX / Core ML / TFLite** 等端侧推理栈将不再仅仅面向"个人生产力"场景,而是被迫承担 **常驻后台合规推理** 的角色。带来的连锁反应包括:端侧模型的 **能耗与热管理** 门槛显著上升、**极低比特量化(BitNet 1.58b / W4A16)** 的重要性从"可选优化"变成"必需项"、以及 **端侧模型可审计性**(权重是否公开、更新链路是否可信)可能被立法强制要求。这条政策脉络值得所有做端侧 LLM/VLM 部署的团队本周内评估。
