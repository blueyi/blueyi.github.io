2️⃣ AI 编译器与框架

  • theregister.comPyTorch 2.15 正面处理「一块坏 GPU 拖垮整集群」问题 🔥
    报道称这次是「把技术债铲到一边」，让大规模 AI 训练更能容忍单卡故障——在万卡级训练里，节点级失败是常态而非异常，框架层的弹性能力开始与算子性能同等重要 。
  • arxiv.orgTauLang：为静态调度加速器设计的时空编程语言与编译器
    Groq TSP 这类芯片去掉了 cache、仲裁器和硬件调度器，编译器必须把每个操作的 slice 与发射周期固定下来——「什么时候执行」成了正确性条件，而不是性能调优项。这为「编译器承担全部调度责任」的加速器给出了可编程的抽象 。
  • arxiv.orgNUMA-Torch：让 TorchInductor 感知 NUMA 的多路 CPU prefill
    参数放不进片上 cache 后，多路 CPU 上的 prefill 吞吐由可持续 DRAM 带宽而非浮点峰值决定，而标准 TorchInductor 路径分配权重时完全不考虑 NUMA 亲和性，跨 socket 流量直接把带宽吃掉一半 。
  • arxiv.orgDMuon：Muon 类矩阵优化器在数据并行下的拓扑感知切分
    Muon 更新整块权重矩阵，与 FSDP（ZeRO-2/3）/HSDP 的元素级或行级分片天然冲突，一旦参数也被分片，就要额外通信或重复计算；DMuon 给每个矩阵指定唯一 owner 来消化这个矛盾 。
  • arxiv.org事件溯源 agent runtime 的 fork 安全性：「可回放」其实是一族断言
    固定日志折叠可以确定，但响应式结算仍对调度敏感；记录 oracle 结果可以实现零调用回放，可原始交互已经改变了成本或世界状态；前缀拷贝也无法撤销已发生的动作——做 agent 快照与分支时，这三件事必须分开验证 。

3️⃣ AI 推理优化（数据中心）

  • arxiv.orgFastAFD：Attention-FFN 拆分在机架级 NVLink 上是否还成立 🔥
    AFD 把 attention 与 MoE 专家分开部署曾报告可提升 decode 吞吐，但此前结论来自别的硬件、更窄的 colocated 基线或解析模型；这篇在 GB200 NVL72 上做实测。同期 Should You Split Decode? 更直接地问：P/D 拆分之上再拆 AFD，多出来的通信、放置约束和第三个资源池，在模型与加速器路线图快速变化时还付得起吗 。
  • arxiv.orgLowRAM：用低秩 key 加摊销 value 做可组合 KV Cache 压缩
    作者观察到同一 attention head 内 value 在很大程度上可由对应 key 预测，于是在「跨 token/跨层/跨特征维度」和「降精度」之外开出第三条正交压缩轴，且可与其他方法叠加，直接缓解 KV cache 随上下文线性增长导致 batch size 上不去的问题 。
  • arxiv.orgLoopDuet：循环 Transformer 的分阶段深度
    循环 Transformer 靠复用共享核心增加推理期算力而不增加参数，但 prefill 与 decode 共用同一个 loop budget 会把两阶段成本绑死；这套免训练方法联合选择两个预算，同时在 prefill 边界保住 decode 深度 。
  • arxiv.orgPSI：固定 GPU 工作集的 22B 音视频生成模型保精度子张量推理
    整块 offload 能降低常驻显存，但要求每个传输块都能塞进预算；这套固定 arena 运行时用「子块权重量流 + 单独管理中间态」的办法，把 BF16 大模型的受管显存占用变成可计算、可复现的常数，对单卡跑大模型的团队有直接参考价值 。
  • qbitai.com腾讯 Hy4 调用量激增，WorkBuddy 已十倍扩容
    官方称 Hy4 在开源模型中 Agent 能力第一，11 月 5 日起因调用量暴涨做了十倍容量扩容——开源权重模型的真实压力点正在从「效果能不能打」变成「服务侧能不能扛住突发流量」 。
