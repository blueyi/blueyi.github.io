1️⃣ AI 芯片

  • bloomberg.com[Moonshot's Kimi uses 20k Nvidia chip cluster from Alibaba](https://www.bloomberg.com/news/articles/2026-07-31/moonshot-s-kimi-built-on-20-000-nvidia-chip-cluster-from-alibaba)
    (HN 103 分)。彭博报道 Kimi 的训练底座是阿里巴巴提供的两万卡级 Nvidia 集群。这条消息的信息量不在"用了多少卡",而在算力供给关系:中国头部模型公司的 Nvidia 算力正通过云厂商的存量集群以租用/入股绑定的形式流转,而非自建。对 infra 从业者的含义是,中国市场的 GPU 竞争正在从"买不买得到"转向"云厂商手里的存量卡如何调度和定价",集群归属与模型公司股权结构高度耦合。
  • arxiv.org[Demystifying DRAM Read Disturbance](https://arxiv.org/abs/2607.28233)
    RowHammer / RowPress 的实验表征与器件级建模之间长期存在鸿沟——大量前人工作基于经验观测提出缓解方案,却缺乏物理机理支撑。该文尝试把实测 bitflip 行为与器件级模型对齐。对于 HBM 时代堆叠密度持续提升的场景,读扰动已不只是安全问题,更是大规模训练集群静默数据损坏(SDC)的潜在来源,值得 infra 团队关注。
  • arxiv.org[A Theoretical Framework for Stochastic Activity Prediction in Tensor Accelerator Wallace-Tree Multipliers](https://arxiv.org/abs/2607.08002)
    指出张量加速器的乘法器即使在稀疏操作数下也每周期烧动态功耗——零检测要求严格为零,结构化功耗门控要求乘法器空闲,离线权重选择又无法响应运行时数据。SAP 试图用随机活动预测填补这个空档。这是"稀疏性红利如何真正兑现为电费"的硬件侧答案。
  • arxiv.org[Analog Courant Numbers and their Role in Analog Computing](https://arxiv.org/abs/2607.27609)
    为模拟计算(以阻抗网络表示矩阵行)给出了一个动力学上界——最快归一化模态不超过所有电路行中最大合成单位增益带宽的 $2\pi$ 倍。相当于给模拟矩阵求解器画了一条"速度天花板",对判断模拟加速器的实际可用带宽很有参考价值。
  • arxiv.org[Nanoparticle Networks for Neuromorphic Computing](https://arxiv.org/abs/2607.27844)
    SiO₂/Si 衬底上金属纳米颗粒经分子结互连,外围静态控制电极把被动 reservoir 变成可调非线性动力系统。属于超前沿探索,离量产极远,但代表了"物理计算"路线在能效上的持续押注。

2️⃣ AI 编译器与框架

  • arxiv.org[BMOA: Baseline-Mechanism-Outcome Attribution for Compiler-Induced Numerical Deviations](https://arxiv.org/abs/2607.27270)
    这是本期编译器方向最实用的一篇。它把"编译器导致的浮点数值偏差"拆成三个独立问题——观察到的差异意味着什么、证据支持哪种编译器行为、由此产生什么数值后果。现有测试流程常把三者塌缩成一个 pass/fail mismatch,导致工程师只知道"数字对不上",不知道是 FMA 融合、重结合优化还是精度提升导致的。对做 kernel 移植、跨编译器版本回归、混合精度训练复现的团队,这套归因框架可以直接借鉴到 CI 里。
  • arxiv.org[Automatic layout of railroad diagrams](https://arxiv.org/abs/2509.15834)
    首次对语法图(syntax diagram)布局做形式化处理,把问题刻画为编译一门"图语言"。虽然是文档工具向,但思路是典型的编译器视角——把可视化当成一次带约束的代码生成,DSL 设计者可参考。
  • arxiv.org[Confluence of conditional rewriting modulo](https://arxiv.org/abs/2504.01847)
    研究 →R/E(模等式集 E 的重写)的合流性,即 E-confluence。这是重写系统类语言(Maude 等)与等式饱和(equality saturation)优化的理论底座,和现代编译器里 egg / e-graph 那一套优化框架同源。
  • arxiv.org[Formalization of security](https://arxiv.org/abs/2607.28551)
    综述性章节,覆盖证明助手在系统安全、语言级安全、安全编译(secure compilation)与密码学中的应用,并强调其对认证(certification)的支撑作用。安全编译是编译器与治理的交叉点,亦见分类 5。
  • arxiv.org[CircuitProver](https://arxiv.org/abs/2607.27259)
    用 Lean 4 做硬件形式验证并沉淀可复用证明库,本质是"证明即编译产物"的复用问题,详见分类 7。
  • arxiv.org[Deep R Programming](https://arxiv.org/abs/2301.01188)
    (旧文回流至列表)是一份系统的 R 语言深度教程,面向数据处理与数值计算,与 infra 关联较弱,仅作存档。

3️⃣ AI 推理优化(数据中心)

  • arxiv.org[SmartGen: Seamless Disaggregated LLM Inference with Selective KV Cache Transfer](https://arxiv.org/abs/2607.28150)
    本期数据中心推理方向最值得读的一篇。Prefill/Decode 分离(PD 分离)已是主流服务架构,但论文精准指出了一个自托管场景下的致命前提缺失:PD 分离默认节点间有超高带宽互联,而在租用的云实例上,节点间带宽有限,巨量 KV cache 传输极易打满内联带宽,反而让分离架构变成负优化。SmartGen 的解法是选择性 KV cache 传输——不是全量搬运,而是判断哪些 KV 值得跨节点传。对所有在公有云上自建 vLLM/SGLang 服务、又没有 RDMA/IB 的团队,这是必读。
  • arxiv.org[Beyond KV Reconstruction: Functional Reconstruction for MLA Draft Models in Speculative Decoding](https://arxiv.org/abs/2607.27269)
    MLA(多头潜在注意力)用紧凑潜在状态替代不断膨胀的 KV cache,是长上下文推理的关键,但绝大多数高质量开源 checkpoint 仍是 MHA/GQA,需要转换才能吃到 MLA 的缓存红利且不重训。该文指出:做投机解码的 draft model 时,不应只追求重建 KV,而应追求功能等价重建。这条思路把"架构转换"和"投机解码"两个热点拼在了一起,是当前推理栈里少见的双重收益点。
  • arxiv.org[SDO: Structure-Aware Data Organization for Efficient LLM Post-Training](https://arxiv.org/abs/2607.27273)
    批评现有做法把数据组织当成静态预处理——基于 embedding 的分组在训练前就固定分区,无法适应训练过程中样本曝光度的演化。SDO 主张让数据组织随优化过程动态调整。虽偏训练侧,但直接决定后训练集群的 GPU 小时账单。
  • arxiv.org[GyRot](https://arxiv.org/abs/2607.27694)
    与 LightRot 同样适用于数据中心推理场景,详述见分类 8。

4️⃣ 数据中心与基础设施

  • arxiv.org[Queue-Theoretic Admission Control for Multi-Tenant GPU Clusters](https://arxiv.org/abs/2607.28223)
    本期基础设施方向的最佳论文。它从一个所有集群运维都痛的现实问题出发——GPU 集群运营方无法告诉用户"你的任务还要排多久",现有系统都是无形式保证的贪心启发式。作者把 GPU 集群准入形式化为多类别、多资源排队网络,并证明了一个结构性分解:待处理队列可划分为可报价工作负载(在稳定性条件下等待时间有界)与不可行工作负载。这意味着集群调度器第一次可以对一部分任务给出有 SLA 意义的等待时间承诺,对内部平台的用户体验和配额谈判都是实质性改进。
  • arxiv.org[FAIR-Compute: A Roadmap for Fair and Efficient Allocation of Federated Digital Research Infrastructure](https://arxiv.org/abs/2607.28290)
    随着 HPC、高吞吐计算与存储需求增长,稀缺算力如何分配——而不只是总量有多少——已成为科研生产力的决定性因素。该路线图把联邦式数字研究基础设施(DRI)的分配问题放在算法博弈论、交通经济学与政策的交叉点上研究。这一视角同样适用于企业内部多 BU 抢 GPU 的场景。
  • arxiv.org[A Taxonomy of Performance Metrics for the Distributed Computing Continuum](https://arxiv.org/abs/2607.28407)
    为分布式计算连续体(DCCS)梳理性能指标分类法。AI 与大规模数据应用把任务越来越多地分散在资源密集的数据中心与边缘之间,传统单点指标已不足以描述系统。做跨云/云边协同可观测性的团队可用作指标体系设计的起点。
  • arxiv.org[A Cloud Continuum Research Infrastructure for Distributed CPS Experimentation](https://arxiv.org/abs/2607.28193)
    基于 SLICES Cloud Continuum Blueprint 提出两级参考架构,强调在异构 Edge/Fog/Cloud/HPC 混合环境下保持可复现性、可观测性与部署控制。CPS 与具身智能实验平台建设可参考。
  • arxiv.org[ESBT: A Scalable and Deterministic Sequence CRDT](https://arxiv.org/abs/2607.28101)
    面向分布式协同编辑的确定性序列 CRDT。虽非 AI infra 主线,但 CRDT 的收敛性设计对多副本状态同步(如分布式 KV/参数服务器的最终一致场景)有借鉴价值。
  • bloomberg.com交叉引用:阿里向 Moonshot 提供 [两万卡 Nvidia 集群](https://www.bloomberg.com/news/articles/2026-07-31/moonshot-s-kimi-built-on-20-000-nvidia-chip-cluster-from-alibaba),是本期最直接的超大规模算力资源流动事件。

6️⃣ 具身智能

  • deepmind.google[Gemini Robotics 2 brings whole body intelligence to robots](https://deepmind.google/blog/gemini-robotics-2-brings-whole-body-intelligence-to-robots/) 🔥
    (HN 609 分,本期最高分)。DeepMind 发布 Gemini Robotics 2,核心卖点是全身智能(whole body intelligence)。这是一个重要的范式移动:此前 VLA 主流仍以"视觉-语言-末端执行器动作"为主,把机器人简化为一条手臂;而全身智能意味着模型需要统筹移动底盘、躯干、双臂与平衡,动作空间和时序耦合复杂度大幅上升。609 分的 HN 热度也印证了具身智能已成为本轮 AI 的主叙事之一。
  • arxiv.org[It's Not Just More Demos: Counterfactual Action Sensitivity Coverage](https://arxiv.org/abs/2607.27261)
    直击视觉模仿学习的老大难——策略对视觉"干扰项"极度脆弱,光照、背景干扰、颜色的轻微变化就能让性能崩塌。通常做法是加数据多样性,但没人知道该加哪些示教。该文提出用反事实动作敏感度覆盖来指导数据采集,把"多采数据"变成"精准采数据",对真机数据成本极高的团队非常实际。
  • arxiv.org[Cross-Embodiment Transfer via Behavior-Aligned Representations](https://arxiv.org/abs/2607.27549)
    研究物体边界框、语言动作描述、末端执行器轨迹等行为对齐表征在跨本体迁移中的作用。大规模模仿学习虽已跨多种本体收集数据,但真正的跨本体迁移仍然困难,这类中间表征是当前最有希望的桥梁。
  • arxiv.org[Failure Detection for Surgical Robot Imitation Policies via Flow-Matching World Modeling](https://arxiv.org/abs/2607.27511)
    手术机器人部署的安全阀。失败数据稀缺、操作高度可变,导致失败检测难做;该文用流匹配世界模型来建模。世界模型作为"运行时监控器"而非"规划器",是一个被低估的方向。
  • arxiv.org[Simulation of Surgical Suturing Using PBD and MPM](https://arxiv.org/abs/2607.27494)
    手术机器人仿真需要同时建模刚性器械、软组织与流体,此前多数工作只单独仿真缝线或软组织。该文做完整的软组织缝合场景,服务于强化学习训练。
  • arxiv.org[Corrigible Assistance in One Round](https://arxiv.org/abs/2607.27508)
    辅助博弈中人知道目标、机器人需推断,在线求最优策略通常要解 POMDP 因而不可行。该文找出一类可用"语用-教学最佳响应"一轮求解的辅助博弈,是可纠正性(corrigibility)从哲学讨论走向可计算的一步。
  • arxiv.org[LabEvolver](https://arxiv.org/abs/2607.27690)
    免训练的湿实验室 agent 经验演化框架,内层做状态接地的感知/规划/安全校验,外层把完成的轨迹蒸馏成可复用的技能、策略与安全经验。"经验即记忆"的 agent 架构在真实实验室场景的落地样本。
  • arxiv.org[Arm2Air](https://arxiv.org/abs/2607.27627)
    (把机械臂避障骨架跨本体迁移到无人机中继编队)与 Vision-Language-Enabled UAV Triage(VLM 灾害响应的系统工程框架),均属具身智能向应急场景的外溢。

7️⃣ AI 自动算子与代码生成优化

  • arxiv.org[ARES: Adaptive Reasoning-Effort Steering for PPA- and Cost-Aware RTL Optimization with LLM Agents](https://arxiv.org/abs/2607.27879)
    本期该分类最重要的一篇,提出了一个被普遍忽视的评价缺陷。LLM agent 通过"编辑→综合→PPA 分析"迭代优化 RTL 的功耗/性能/面积,每次调用都在烧钱,但现有工作只报告达到的质量、不报告归一化成本,还把质量归功于精心设计的跨设计记忆,并且每次调用的推理努力固定不变。ARES 主张按需自适应调节推理强度。这对所有做 LLM 驱动自动优化的团队都是当头一棒:没有成本轴的质量提升不是提升,只是花更多 token 买分数。
  • arxiv.org[RLPF: Reinforcement Learning from Performance Feedback for Code Generation](https://arxiv.org/abs/2607.27271)
    代码模型普遍用执行反馈训练,但信号止步于正确性。对系统代码而言这是致命缺口——两个程序可以通过完全相同的测试,运行时却差出数量级。RLPF 研究如何训练 code agent 偏好"更快的正确实现",把效率从评估指标提升为训练信号。这正是自动算子生成(kernel 生成、autotuning)最需要的那块拼图。
  • arxiv.org[CircuitProver: Agentic Lean 4 Theorem Proving with Reusable Circuit Proof Library](https://arxiv.org/abs/2607.27259)
    主流硬件形式验证靠模型检查,每个设计实例单独验证、只暴露 pass/fail,证明背后的推理被锁在 solver 启发式里,相关设计间反复重建。CircuitProver 用 agentic Lean 4 定理证明 + 可复用电路证明库,把"一次性验证"变成"可积累资产"。这与 ARES 一起,勾勒出 LLM agent 进入 EDA 全流程的两条主线:优化与验证。
  • openai.com交叉引用:[GPT-5.6](https://openai.com/index/advancing-the-price-performance-frontier-with-gpt-5-6/) 的性价比推进直接影响上述所有 LLM-in-the-loop 优化流程的经济性——而 [Bottleneck Labs 的实测](https://www.bottlenecklabs.com/blog/autonomously-run-businesses)提醒我们,把优化循环完全交给 agent 自主运行仍有风险。

8️⃣ 边缘与端侧推理
