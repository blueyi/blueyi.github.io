14 多模型/多任务编排洞察

  • 章节编号:14
  • 所属层:R 运行时层(承接 12 IREE VM、13 实时/QoS、09 MIG、21 双系统 VLA)
  • 洞察轮次:Round 3
  • 负责人 / 评审人:Runtime 负责人(主)+ 实时调度(13) + 模型工程师 + Driver(09)
  • 状态:草稿 v3(统一论证风格:调研→对比→待选型)
  • 关联 ADR:ADR-099(多 VM/多 context 编排模型)、ADR-100(GR00T/Gemini 双系统流水线)、ADR-101(RTC 与 chunk 调度)、ADR-102(资源仲裁:QoS/MIG/内存组)
  • 上游依赖:09(context/MIG)、11(power profile)、12(IREE VM)、13(QoS/抢占)、21(π0/GR00T/Gemini)

1. 范围与目标​

定义端侧 多模型并发、多任务流水线、动态 shape、资源仲裁 的运行时编排。13 章管 OS/RTOS 分域;本章管 NPU/IREE 域内 多 graph/多 VM。

核心问题

  1. GR00T VLM+DiT、Gemini VLA+ER、Helix S2/S1/S0 如何映射到 runtime?
  2. Thor MIG 式分区 vs 软件 QoS 如何选型?
  3. π0 RTC 双缓冲在编排层的语义?
  4. TOP 方案(TensorRT multi-engine、IREE multi-module、QNN multi-context)对比?
  5. 感知 CNN + VLA + 小控制网 同时在线 如何仲裁?

论证风格:本章为设计前洞察,按 业界调研(§3) → 对比矩阵(§4) → 初步倾向(待选型,非定论)(§6) 展开;洞察阶段不锁定方案;正式决策见 ADR/选型矩阵。术语见 embodied-intelligence-glossary.md。

2. 需求洞察(具身驱动)​

场景编排模式来源

2.2 硬性指标​

  • GR00T 级:DiT ≥10Hz 与 VLM ≥3Hz 并发不互相 OOM。
  • RTC:执行 chunk N 时 chunk N+1 须已就绪或 inpaint。
  • context 切换 ≤50ms(换 task,非 1kHz 环)。
  • 内存:128GB 统一内存 场景下 ≥3 context 预留(对标 Thor)。

维度内容

3.6 趋势​

  1. 双系统/三系统成 TOP 标配(GR00T/Gemini/Helix)。
  2. RTC 从论文进 runtime API(21/12)。
  3. MIG 硬件分区 + 软件 pipeline 组合(Thor)。
  4. ActionFlow 类跨请求调度 与 RTC 叠加 提 effective Hz。

4. 候选方案​

候选性能确定性成本小结
A. IREE multi-module + priority stream + RTC544初步倾向候选
B. 单 VM 串行355M1 only
C. 每模型独立 OS 进程432内存开销大

倾向:A;硬件 MIG 式 memory group(09) 可选增强。

6. 结论与 ADR​

  1. IREE multi-module/multi-VM 表达 GR00T/Gemini/Helix 拓扑。
  2. RTC 双缓冲 为一等编排原语(非应用 hack)。
  3. QoS:DiT > 感知 > 后台;11 power 降档时 drop 后台 context。
  4. 对标 TRT multi-engine + MIG;差异化 manifest link.yaml + 可 git 编排。
  • ADR-099 编排模型(待选型):IREE module graph;manifest orchestration: 字段(pipeline/parallel/rtc)。
  • ADR-100 双系统流水线(待选型):VLM→DiT link tensor;Pipelined 默认;Sequential 可配。
  • ADR-101 RTC/chunk(待选型):双 buffer;inpainting;与 21 chunk_size 绑定。
  • ADR-102 资源仲裁(待选型):priority stream;memory group;与 09 MIG/QoS、13 抢占联动。
