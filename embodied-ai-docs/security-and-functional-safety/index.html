28 安全与功能安全洞察

  • 章节编号:28
  • 所属层:X 横切(贯穿 04 安全岛、09/10 BSP、22/23 部署)
  • 负责人 / 评审人:安全架构师(主)+ OS/BSP + SDK + 硬件(安全岛)
  • 状态:草稿
  • 关联 ADR:ADR-091(安全启动与信任链)、ADR-092(模型与制品加密/签名)、ADR-093(TEE/密钥存储边界)、ADR-094(功能安全与 ISO 26262/机器人映射)
  • 上游依赖:04(安全岛 ASIL-D)、10(secure boot/A/B)、22(bundle 签名)、23(OTA/provisioning)

1. 范围与目标​

定义 secure boot、制品签名、模型保护、TEE/密钥、功能安全与机器人场景映射。扩展阶段 到 架构与 ADR;完整认证 规模化阶段+。

核心问题

  1. bundle/firmware/rootfs 信任链?
  2. 模型 IP 保护(权重加密)?
  3. 安全岛 ASIL-D(04) 与 Linux AI 域隔离?
  4. 对标 Jetson secure boot、QNX safety、Qualcomm IQ10?
  5. 隐私(摄像头数据)合规?

2. 需求洞察(具身驱动)​

场景安全诉求
产线 provisioning设备唯一密钥;防克隆
VLA OTA签名 bundle;防篡改
客户模型 IP加密 weights;TEE 解密
人形协作功能安全 控制路径;AI 非 SIL
工厂视频默认不上云(24/28)

硬性指标:启动链 verify 100%;OTA reject 未签名;密钥 不可导出 plaintext。

3.2 信任链(候选)​

ROM → signed SPL/U-Boot → signed kernel+dtb → signed rootfs
 → signed dsa-bundle(22) → IREE verify → load weights

密钥层次:设备 OEM key → per-device key(23 provisioning) → model CEK in TEE。

3.7 趋势​

  1. signed model artifact 与 signed firmware 同等重要(23 OTA)。
  2. AI 非 SIL 成行业共识;ER/supervisor 双系统兴起。
  3. ExecuTorch/Mobile 推动 on-device attestation——机器人可借鉴 provisioning(23)。
  4. 隐私默认本地(24)——欧盟/中国 PIPL 强化 field video 约束。

4. 候选方案​

候选小结
A. Secure boot + signed bundle + TEE 密钥 + 岛 SIL建议方案
B. 仅 HTTPS OTA 无 secure bootM1 禁止量产
C. 全 QNX ASIL车规旗舰可选(10 章)

6. 结论与 ADR​

  1. 全链签名:boot→rootfs→bundle。
  2. 权重加密+TEE unwrap;IP 保护。
  3. VLA=best-effort;1kHz=岛+功能安全证据包(长期)。
  4. 隐私默认本地。
  • ADR-091 安全启动（草案）:U-Boot→kernel→rootfs verify;fuse 策略;10 ADR-060 衔接。
  • ADR-092 制品签名加密（草案）:bundle sign mandatory;weights encrypt optional(mandatory 客户 IP);Runtime verify。
  • ADR-093 TEE/密钥（草案）:provisioning per-device key;CEK in TEE;控制密钥 岛内。
  • ADR-094 功能安全映射（草案）:AI 域 非 SIL;控制 岛 ASIL 目标;freedom from interference 04/09;VLA 须 supervisor+watchdog。
